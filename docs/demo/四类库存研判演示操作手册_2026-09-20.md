# 四类库存研判演示操作手册（2026-09-20）

## 1. 演示目标

用同一个营业日完整展示四类库存研判：

| 规则 | 场景 | 演示状态 | 当前责任人 |
|---|---|---|---|
| D2 负库存 | 黑糖珍珠漏确认收货 | 已闭环 | 总部已验收 |
| D1 盘点差异 | 牛奶实盘与理论库存不符 | 待处理 | STORE001 门店 |
| S1 低于安全库存 | 茶叶低于安全库存且门店无法独立调货 | 待处理 | 区域督导 Rina |
| T2 销入比异常 | 果糖批量到货但当日销售消耗很低 | 待处理 | STORE001 门店 |

首页应严格显示 4 张工单：1 张已闭环、3 张待处理。

## 2. 数据边界

### 真实来源

- 门店：`STORE001 · 小茶日记`
- 营业日：`2026-09-20`
- 数据来源：飞书 Base 销售同步
- 当日数据：7 条销售记录、10 杯、销售额 211
- 同步批次：以 `/sync/` 页面当前批次为准

### 明确标记的 Demo 业务事实

- D2：补建 2,000g 黑糖珍珠订货单和收货单，用于演示漏收货修正与闭环；
- D1：牛奶实盘 80L、理论库存 130L，用于演示盘点差异；
- T2：果糖批量收货 10kg、当日销售 BOM 消耗约 0.03kg，用于演示销入比异常；
- S1：由真实营业日台账回算出的茶叶安全库存信号，后续督导流转是 Demo 流程数据。

演示开场应主动说明：销售是真实同步数据，补录收货、实盘和批量到货是用于验证闭环的模拟业务动作。

## 3. 推荐演示路线

### 第一步：总部查看数据基线

1. 打开 `/hq-login/`，选择总部运营“王敏”。
2. 进入“飞书同步” `/sync/`。
3. 展示最新有效营业日为 2026-09-20，并说明 7 条、10 杯、销售额 211。
4. 返回总部首页 `/`，确认筛选数量为：全部 4、待处理 2、门店处理中 0、待总部确认 1、已闭环 1。不同页面对待处理状态的文案可能不同，但总数必须为 4，未关闭必须为 3。

### 第二步：展示 D2 已闭环链路

1. 打开“D2 · 已闭环”的黑糖珍珠工单。
2. 展示异常来源、库存重算公式和首次 V2 快照。
3. 展示门店核查记录：2,000g 已到货，但遗漏收货确认。
4. 展示关联订货单、收货单及 2,000g 入库流水。
5. 展示最新 V2：负库存不再触发，理论库存恢复为正数。
6. 展示最终原因、解决方式、门店采纳、总部确认和关闭时间线。

这一段要讲清楚：发现问题 → 人工核对 → 正式业务单据 → 库存入账 → 规则重算 → 人工验收关闭。

### 第三步：展示三个未闭环案例

#### D1 牛奶盘点差异

1. 打开“D1 · 待门店处理”。
2. 展示盘点证据：实盘 80L、理论库存 130L。
3. 说明系统不会直接改库存，门店仍需核对收货、报损、单位和盘点录入。
4. 保持待处理，用来演示“有证据但尚未形成最终原因”。

#### S1 茶叶低于安全库存

1. 打开“ S1 · 待督导处理”。
2. 展示门店结论：没有待收货单，也无法独立确认附近门店可调数量。
3. 在移动端 `/login/` 选择“Rina”，确认工单进入督导视角。
4. 说明下一步是跨店核对并建立调拨；辖区无货时再升级总部供应链。

#### T2 果糖销入比异常

1. 打开“ T2 · 待门店说明”。
2. 展示 10kg 批量到货与约 0.03kg 销售 BOM 消耗的对比，销入比约为 0.003。
3. 说明待核对项：集中备货、半成品生产、收货单位或数量录入错误。
4. 保持待处理，用来说明规则只提出可验证假设，不替代人工结论。

### 第四步：前后台一致性

1. 移动端 `/login/` 选择“陈店长”或“小李”，查看门店可处理的 D1、T2 和相关任务记录。
2. 退出后选择“Rina”，查看已升级的 S1 工单。
3. 回到总部首页，确认仍为 4 张：D2 已闭环；D1、S1、T2 未闭环。

## 4. 演示时不要误操作

- 可以刷新页面、切换角色、查看工单详情和关联单据；
- 不要再次确认 D2 收货单；
- 不要关闭 D1、S1、T2，除非下一场演示就是继续处理这三个案例；
- 不要执行 Demo 重置、生成演示销售或清理工单；
- 如状态被改乱，使用下方受保护接口重新准备。

## 5. 重新准备四类演示数据

先确认飞书最新有效营业日仍是 2026-09-20，再以总部身份调用：

```http
POST /api/demo-day/prepare-four-case-showcase
Content-Type: application/json

{
  "store_code": "STORE001",
  "business_date": "2026-09-20",
  "confirm": "PREPARE4:STORE001:2026-09-20"
}
```

接口会把当前可见工单备份到独立 R2 对象，清理上一次四类演示产生的业务事实，再生成固定的 4 张演示工单。该操作会改变线上 Demo 状态，只能在确认门店和营业日后执行。

# 四类库存研判演示操作手册（2026-09-20）

## 1. 演示目标

用同一个营业日完整展示四类库存研判：

| 规则 | 场景 | 演示状态 | 当前责任人 |
|---|---|---|---|
| D2 负库存 | 黑糖珍珠负库存 | 已创建工单、待执行 | STORE001 门店 |
| D1 盘点差异 | 牛奶实盘与理论库存不符 | 仅研判、待建单 | 总部运营 |
| S1 低于安全库存 | 物料低于安全库存 | 仅研判、待建单 | 总部运营 |
| T2 销入比异常 | 果糖批量到货但当日销售消耗很低 | 仅研判、待建单 | 总部运营 |

库存研判页应严格显示 4 个持续问题：1 个已经建立跟进工单，另外 3 个没有工单，留给演示者体验“查看研判 → 选择建议 → 创建工单”。总部任务中心只应显示这一张预建工单。

## 2. 数据边界

### 真实来源

- 门店：`STORE001 · 小茶日记`
- 营业日：`2026-09-20`
- 数据来源：飞书 Base 销售同步
- 当日数据：7 条销售记录、10 杯、销售额 211
- 同步批次：以 `/sync/` 页面当前批次为准

### 明确标记的 Demo 业务事实

- D2：保留真实销售触发的负库存研判，并预先创建一张待执行工单；不预填最终原因，不替用户完成闭环；
- D1：牛奶实盘 80L、理论库存 130L，用于演示盘点差异；
- T2：果糖批量收货 10kg、当日销售 BOM 消耗约 0.03kg，用于演示销入比异常；
- S1：由真实营业日台账回算出的茶叶安全库存信号，后续督导流转是 Demo 流程数据。

演示开场应主动说明：销售是真实同步数据，补录收货、实盘和批量到货是用于验证闭环的模拟业务动作。

## 3. 推荐演示路线

### 第一步：总部查看数据基线

1. 打开 `/hq-login/`，选择总部运营“王敏”。
2. 进入“飞书同步” `/sync/`。
3. 展示最新有效营业日为 2026-09-20，并说明 7 条、10 杯、销售额 211。
4. 进入库存研判 `/diagnosis-v3/`，确认只显示 D2、D1、S1、T2 四个问题，其中 D2 显示已关联工单，另外三个显示尚未建单。

### 第二步：展示 D2 已建单、待执行链路

1. 打开 D2 黑糖珍珠研判，并进入其关联工单。
2. 展示异常来源、库存重算公式和首次 V2 快照。
3. 展示工单创建后的执行说明：先核对实物、收货、调拨签收和订货记录。
4. 说明此时还没有最终原因，也没有自动修改库存；门店需执行核对并回传。
5. 可在演示中继续建立收货、盘点或调拨动作，再观察 V2 重算和闭环门禁。

这一段要讲清楚：研判只负责形成可解释结论；运营确认需要跟踪后才创建工单，工单再承载执行、证据、重算和闭环。

### 第三步：亲自从三个研判中创建工单

#### D1 牛奶盘点差异

1. 打开 D1 牛奶研判。
2. 展示盘点证据：实盘 80L、理论库存 130L。
3. 说明系统不会直接改库存，门店仍需核对收货、报损、单位和盘点录入。
4. 由你决定是否创建工单；未创建前它只是一个待运营确认的持续问题。

#### S1 茶叶低于安全库存

1. 打开 S1 低于安全库存研判。
2. 查看当前库存、安全库存和建议补货/调拨动作。
3. 需要跟踪时再创建工单，并在工单中决定门店处理或分配区域督导。

#### T2 果糖销入比异常

1. 打开“ T2 · 待门店说明”。
2. 展示 10kg 批量到货与约 0.03kg 销售 BOM 消耗的对比，销入比约为 0.003。
3. 说明待核对项：集中备货、半成品生产、收货单位或数量录入错误。
4. 需要跟踪时再创建工单，用来说明规则只提出可验证假设，不替代人工结论。

### 第四步：前后台一致性

1. 移动端 `/login/` 选择“陈店长”或“小李”，查看预建的 D2 门店执行任务。
2. 当你从 D1、S1 或 T2 创建并分配工单后，再切换相应门店或督导身份验证责任流转。
3. 回到总部库存研判页，确认建单状态与工单中心一致。

## 4. 演示时不要误操作

- 可以刷新页面、切换角色、查看工单详情和关联单据；
- D2 尚未建立修正单据，可自由体验核对、补录和闭环；
- D1、S1、T2 默认没有工单，可逐个体验创建；
- 不要执行 Demo 重置、生成演示销售或清理工单；
- 如状态被改乱，使用下方受保护接口重新准备。

## 5. 重新准备四类演示数据

先确认飞书最新有效营业日仍是 2026-09-20，再以总部身份调用：

```http
POST /api/demo-day/prepare-four-case-showcase
Content-Type: application/json

{
  "store_code": "STORE001",
  "business_date": "2026-09-20",
  "confirm": "PREPARE4:STORE001:2026-09-20"
}
```

接口会把当前研判和可见工单备份到独立 R2 对象，清理旧研判、旧工单及其演示单据，再生成固定的 4 个研判，并只为 D2 创建一张工单。销售、基础库存、BOM 和飞书同步批次不会被删除。该操作会改变线上 Demo 状态，只能在确认门店和营业日后执行。

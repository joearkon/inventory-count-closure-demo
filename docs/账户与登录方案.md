# 账户与登录方案（项目记录）

## 目标

- 总部：使用飞书账号登录并同步人员基础信息。
- 门店：支持 OAuth 或邮箱一次性验证码登录。
- 所有库存写操作记录账号、角色、门店范围、时间和来源设备。

## 角色

- 总部管理员：账号、主数据、门店范围和系统配置。
- 总部运营：研判、工单、盘点下发和单据查看。
- 商品/供应链：BOM、单位换算、安全库存和补货调拨。
- 加盟商管理员：仅查看所属加盟商门店。
- 店长/店员：仅操作授权门店；店员不能修改主数据。

## 推荐实现

### 总部飞书

1. 建立飞书 OAuth 应用，回调至 Worker。
2. 首次登录读取飞书用户 ID、姓名、邮箱和部门；不得保存飞书密码。
3. 本地账户以飞书 open_id/union_id 唯一绑定，门店与角色由总部管理员配置。
4. 定期同步人员启停状态；停用账号立即失效。

### 门店

- 首选：品牌统一身份 OAuth。
- 过渡：邮箱一次性验证码，不使用长期密码。
- 每个账号必须绑定一个或多个门店；切换门店需重新校验权限。

## D1 数据模型建议

- accounts：身份主体、来源、状态、显示名、邮箱。
- account_identities：feishu/openid/email 等外部身份。
- roles、account_roles：角色和授权。
- account_store_scopes：可访问门店。
- login_sessions：哈希后的会话令牌、过期时间、设备摘要。
- auth_audit_logs：登录、失败、登出和权限拒绝。

## 安全边界

- OAuth client secret 与邮件服务密钥只存 Worker Secret。
- Cookie 使用 HttpOnly、Secure、SameSite=Lax；会话可撤销。
- 任何 API 不能信任前端传入的门店编码，必须按服务端授权范围复核。
- 导入现有个人飞书账号前，需要先确定飞书 App ID、回调域名、可读取的用户字段和管理员授权范围。

## 上线顺序

1. 先建表与审计，不阻断现有 Demo。
2. 总部飞书 OAuth 小范围启用。
3. 门店邮箱验证码试点。
4. 权限回归后再强制登录。

## Demo 落地状态（2026-09-18）

后台已增加“系统配置 → 账户与角色”，用于先把组织和工单责任流转跑通：

- 内置门店店员、门店店长、区域督导、总部运营、总部管理员五类角色。
- 内置小李、陈店长、Rina、王敏四个演示账号。
- 可维护姓名、邮箱、身份来源、角色、启停状态和门店／区域／全品牌数据范围。
- 可切换“当前演示身份”，后台所有页面顶部显示当前人员，并将切换动作写入审计记录。
- 已校验邮箱唯一、角色必选、门店／区域范围必选、总部角色才能访问全品牌，以及当前身份不能直接停用。

当前阶段刻意不做权限强制拦截。它是可配置的身份与权限预演，用来验证页面、工单责任和组织范围；不是正式认证。下一阶段需按以下顺序推进：

1. 将账户、身份、角色、授权范围与会话迁移到 D1。
2. 接入总部飞书 OAuth 和门店邮箱验证码／品牌 OAuth。
3. 增加服务端授权中间件，不再信任前端传入的门店编码。
4. 按角色和数据范围过滤总部、督导、门店页面及 API。
5. 完成越权、停用、会话撤销和审计回归后再强制登录。

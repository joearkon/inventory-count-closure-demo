# 库存异常判定知识库（MVP 提炼）

> 来源：用户上传《库存异常判定常用 Knowhow.md》。本文件是产品化提炼，不替代原文。现阶段仅供规则设计、证据说明与人工复核参考，不直接定责，不自动修改库存。

## 1. 统一计算口径

理论期末库存：

期初 + 收货 + 调拨入 − 销售 BOM 消耗 − 调拨出 − 报损 = 理论期末

任何研判必须同时记录门店、营业日、物料、基础单位、数据版本和来源单据。缺少单位换算、BOM、销售、期初或有效单据时，应显示“证据不足”，不能直接归因。

## 2. MVP 首批四类规则

### D2 负库存

- 触发：理论期末小于 0。
- 优先级：最高。
- 首要证据：期初、收货、调拨入/出、报损、销售 BOM 消耗、单位换算。
- 第一排查位置：到货/收货未录、调拨签收、期初、BOM 与单位换算。
- 人员动作：核对到货、收货单和调拨签收；必要时补盘指定物料。
- 系统动作：建立跟进工单或定向盘点草稿；不得直接补库存。

### D1 理论与实盘差异

- 触发：实盘与理论差异超过物料容差。
- 优先级：第二。
- 差异：实盘 − 理论；差异率应以适合物料的分母计算并防止除零。
- 首要证据：最近有效实盘、盘点照片/确认项、当期完整流水、BOM、单位换算。
- 第一排查位置：盘点录入、报损、收货、调拨与主数据。
- 系统动作：沿用原问题建立复核盘点，不重复创建同门店同物料同规则工单。

### S1 安全库存预警

- 触发：理论库存低于门店物料安全库存。
- 优先级：第三；若已经负库存，只作为伴随信号。
- 首要证据：安全库存配置、理论期末、近期销量/消耗、在途补货或调拨。
- 第一排查位置：门店补货节奏、收货/在途调拨、安全库存配置。
- 系统动作：生成补货或调拨建议草稿，由人员确认。

### T2 销入比失衡

- 触发：消耗显著高于入库，或入库显著高于消耗；阈值需按物料类别校准。
- 优先级：第四。
- 首要证据：观察窗口内收货、调拨入、销售 BOM 消耗、报损与期末。
- 第一排查位置：补货节奏、商品销售变化、BOM/单位口径。
- 系统动作：提示核对补货节奏或商品动销，不自动生成责任结论。

## 3. 归因表达规范

每张研判卡固定为：

1. 最可能发生位置（待验证）
2. 支撑证据（带时间窗口和数值）
3. 尚缺证据
4. 人员下一步
5. 可建立的关联单据/页面
6. 验证后的关闭条件

归因位置统一为：门店执行、门店补货、总部供应/采购、商品与主数据、数据与系统。无证据时使用“待验证假设”，禁止写成已认定责任。

## 4. 证据与优先级

- 优先级：D2 → D1 → S1 → T2。
- 同一问题只保留一个主规则，其余作为伴随信号，避免重复工单。
- 直接证据优先于统计基线，统计基线优先于知识库推测。
- “0 收货、0 调拨入”等数值必须标注窗口，例如今日、近 3 日、近 7 日。
- 盘点已经提交时，页面不得继续显示“待盘点”；应显示盘点单号、提交时间和实盘结果。

## 5. 后续知识候选（暂不启用）

原 Knowhow 还覆盖质量、时效、结构、批次/保质期、ABC 分类、季节性、门店业态差异、鲜制茶饮的备料和废弃、错误收货物料、销售同步、BOM 版本与制作出成率等规则。它们应在数据字段、阈值和验证样本齐备后逐项版本化启用，不能一次性成为自动研判规则。

## 6. LLM 使用边界

MVP 第一阶段研判不调用 LLM。规则引擎负责触发、排序、证据和动作模板；LLM 未来只用于知识检索、解释和最小追问，不负责计算、不定责、不自动下发、不改库存。

# 设计稿与线上版本差异（2026-09-18）

## 1. 核对范围

- vNext 设计稿：`prototypes/operations-reminders-vnext/index.html`
- 线上移动端：`/store/?store=STORE001`
- 线上总部端：`/`、`/task-create/`、`/work-order/`
- 登录入口：`/login/`、`/hq-login/`
- 核对方式：页面只读检查、前端源码对照、服务端数据契约检查和本地多角色回归。

本次没有在生产环境创建或关闭任务。所有写入验证均运行于一次性本地 D1/R2 环境。

## 2. 总结

当前不是“设计稿完全没有落地”，而是三种完成度并存：

1. 门店移动端的视觉骨架和三栏信息架构已基本按 vNext 落地。
2. 总部后台仍沿用原来的运营后台外壳，工单闭环能力较完整，但总览和任务中心没有按 vNext 重构。
3. 督导已有账号、辖区数据隔离和协助记录能力，但还没有独立工作台，也没有正式的工单转派模型。

## 4. 数据契约差异

当前 `POST /api/operation-tasks` 已保存：

- 门店；
- 营业日；
- 任务类型；
- 标题与执行要求；
- 来源异常、规则和关联单据。

设计稿要求但当前任务实体尚未正式保存：

- 下发范围类型（单店、区域内多店、区域督导）；
- 截止时间；
- 责任角色和具体责任账号；
- 验收凭证要求；
- 区域任务的逐店完成进度；
- 草稿、已下发、已接收、执行中等更细状态；
- 转派原因、接收时间、退回原因和责任变更审计。

因此不能直接把原型表单接到现有接口。应先升级任务数据契约，避免界面看似完整但服务端丢字段。

## 5. 推荐落地顺序

1. 先补任务责任模型和转督导链路。
2. 再将 vNext 任务中心表单接入真实接口，支持单店、区域、督导三类对象。
3. 给督导增加独立移动首页，显示辖区风险、待接收协助和巡店任务。
4. 最后重做总部总览首屏；现有库存、单据、研判和工单页面继续复用，不重复建设。

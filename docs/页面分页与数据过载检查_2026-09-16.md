# 页面分页与数据过载检查（2026-09-16）

## 结论

本轮检查覆盖总部首页、库存台账、库存流水、库存研判、库存模拟器、盘点计划、库存单据、调拨管理、物料风险、飞书同步、通知、知识库、语音验收和门店移动端。

已发现并处理两类风险：

1. 高增长列表直接渲染全部记录，数据增加后页面会无限拉长。
2. 页面即使只显示少量记录，仍下载完整 R2 状态、图片预览和飞书导入快照。

## 已实施

| 页面 / 区域 | 处理方式 |
| --- | --- |
| 库存流水 | 每页 20 条；门店、物料、方向、业务标签或日期变化时回到第 1 页 |
| 库存单据 | 每页 20 条；筛选变化时回到第 1 页 |
| 盘点计划中心 | 每页 10 张；新建或刷新计划后回到第 1 页 |
| 库存研判 | 每页 10 个异常信号；查看维度或筛选变化时回到第 1 页 |
| 库存模拟器 | 每页 15 笔模拟流水；切换门店或新增流水后回到第 1 页 |
| 调拨管理 | 飞书调拨、系统调拨、库存档案分别每页 10 条 |
| 总部首页盘点概览 | 只显示最新 6 张，并链接至完整盘点计划中心 |
| 物料风险页的计划 / 凭证 | 各显示最新 10 条，并链接至对应完整分页页面 |
| 首页异常工作区 | 原有待处理 / 已闭环分页继续保留 |

以下区域为固定或低数量集合，暂不增加分页：门店主档 6 家、商品主档 18 个、物料主档 20 项、语音验收 9 条、通知设置、飞书同步状态和单物料台账明细。门店移动端接口已按当日和当前门店限定，任务最多 20 条、调拨最多 50 条、凭证最多 20 条。

## 仍需关注的架构边界

当前 R2 仍以单个 current-state JSON 保存演示状态。页面专用视图解决了浏览器下载与渲染过载，但 Worker 在服务端仍需读取整个 current-state 对象。若未来进入长期生产并积累数万笔单据或流水，应将流水、单据、计划和工单迁移为 D1 分表或 R2 分对象存储，并改成基于游标的服务端分页；不能继续无限扩展单个 JSON。

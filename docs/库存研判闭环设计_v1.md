# 库存研判闭环设计 v1

## 目标

闭环不是“上传凭证后关闭工单”，而是保留发现、判断、执行、验证和人工结论的完整链路。规则负责重算事实，人负责解释最终原因和承担业务决策。

## 最小闭环

```text
发现异常
→ 冻结首次 V2 研判快照
→ 建立跟进工单
→ 执行并关联盘点/调拨/订货/收货/报损单据
→ 重新运行 V2
→ 比较处理前后结果
→ 人工选择闭环结果
→ 已恢复 / 接受例外 / 误判 / 转治理 / 继续处理
```

## 工单必须保存的内容

### 首次快照

- 来源研判编号、门店、营业日、物料和单位；
- V1 规则、V2 规则及版本；
- 库存重建值、实盘值和证据引用；
- 首要排查位置、第一假设、缺失证据；
- 决策轨迹和建议动作 ID。

### 执行记录

- 人工处理记录；
- 关联盘点单、调拨单、订货单、收货单、报损单和库存流水；
- 每次操作人、时间、动作前后状态；
- 单据只关联，不覆盖首次研判快照。

### 验证快照

- 业务动作完成后手动或自动重新运行 V2；
- 每次运行生成新的 `diagnosis_run_id`；
- 保存新事实、规则版本、异常状态和缺失证据；
- 页面并排展示首次与最新结果，禁止覆盖历史。

## 人工闭环结果

| 结果 | 使用条件 | 后续动作 |
|---|---|---|
| 已恢复 | 最新 V2 不再触发，且关键单据已关联 | 正常关闭 |
| 接受例外 | 仍触发，但属于经授权的正常业务情况 | 填写理由、批准人和有效期，超期复查 |
| 规则误判 | 事实正确但规则不适用 | 关闭工单，进入规则改进清单 |
| 主数据问题 | BOM、单位、价格、安全库存或映射错误 | 转总部治理工单，原工单等待治理后复算 |
| 尚未解决 | 仍触发且不能合理解释 | 不允许关闭，继续执行或升级 |

## 关闭门禁

MVP 正常关闭至少满足：

1. 有处理记录；
2. 有关联业务单据、盘点结果或明确的人工核查说明；
3. 最新一次 V2 运行时间晚于关键处理动作；
4. 填写最终原因、解决方式、操作人和总部确认；
5. 若最新结果仍触发，只能选择“接受例外 / 规则误判 / 主数据问题”，不能标记为“已恢复”。

## 自动与人工边界

系统可以自动：

- 保存首次研判快照；
- 打开并预填业务草稿；
- 监听关联单据状态；
- 单据确认后触发重新研判；
- 对比前后结果并建议关闭或继续。

系统不得自动：

- 修改库存；
- 提交正式订货、收货、报损或调拨；
- 认定责任人；
- 选择接受例外；
- 最终关闭工单。

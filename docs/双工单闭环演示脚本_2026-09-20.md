# 双工单闭环演示脚本（2026-09-20）

> 目标：演示时只保留两张工单——一张已经形成完整闭环，一张仍未解决并升级区域督导。销售依据为飞书 Base 的 2026-09-20 真实销售；为了演示处理动作，订货、收货和督导流转为明确标记的 Demo 业务数据。

## 演示数据基线

- 门店：`STORE001 · 小茶日记`
- 营业日：`2026-09-20`
- 飞书同步批次：以 `/sync/` 页面当前批次为准
- 当日真实销售：7 条、10 杯、销售额 211
- 规则发现：黑糖珍珠理论负库存；茶叶低于安全库存
- 首页工单：严格保留 2 条

## 案例一：已闭环

**黑糖珍珠（g）调拨 / 收货核查**

1. 飞书销售同步后，BOM 消耗 90g；理论库存从 -1,090g 降至 -1,180g，触发 D2 负库存。
2. 总部建立跟进工单并下发门店核对。
3. 门店店长确认 2,000g 已经到货，但遗漏收货确认。
4. 门店补建订货单、收货单并人工确认收货。
5. 系统生成 2,000g 收货入库流水并自动运行 V2。
6. 理论库存变为 820g，原负库存规则不再触发。
7. 总部填写最终原因、解决方式、操作人和采纳状态，完成验收关闭。

演示重点：真实销售触发 → 门店核对 → 业务单据 → 库存流水 → V2 前后快照 → 人工闭环门禁。

## 案例二：未闭环

**茶叶（kg）补货 / 调拨跟进**

1. 理论期末 1.74kg，低于 2kg 安全库存，触发 S1。
2. 总部建立跟进工单并下发门店。
3. 门店确认没有待收货单，也无法独立确认附近门店的可调数量。
4. 总部记录“尚未解决”，不得关闭工单。
5. 工单转给区域督导 Rina，由其核对辖区门店可调库存；无货时再升级总部供应链紧急补货。

演示重点：门店无法解决时不能假闭环；责任、原因、下一步和督导流转都保留在时间线。

## 推荐演示顺序

1. 总部登录 `/hq-login/`，人物选择“王敏”。
2. 打开 `/sync/`，展示 9 月 20 日真实销售、BOM 和最新同步批次。
3. 回到 `/`，说明首页只有两张工单：1 张督导处理中、1 张已闭环。
4. 打开黑糖珍珠工单，依次展示首次/最新 V2、订货单、收货单、库存流水、闭环结论和时间线。
5. 移动端 `/login/` 选择“陈店长”或“小李”，展示同一工单在门店任务中的处理记录。
6. 移动端退出后选择“Rina”，展示茶叶工单已转给区域督导。
7. 回总部打开茶叶工单，展示“仍触发”、最近一次未解决结论、责任人和下一步动作。

## 可重复准备

总部权限调用：

```http
POST /api/demo-day/prepare-two-case-showcase
Content-Type: application/json

{
  "store_code": "STORE001",
  "business_date": "2026-09-20",
  "confirm": "PREPARE:STORE001:2026-09-20"
}
```

执行前必须确认飞书最新有效营业日为 2026-09-20。旧首页工单会备份到独立 R2 对象，不再进入业务列表；重复执行会清理上一次双工单演示生成的订货、收货和库存流水，再重新构建两条链路。

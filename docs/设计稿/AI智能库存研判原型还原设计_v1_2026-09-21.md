# AI 智能库存研判原型还原设计 v1

日期：2026-09-21  
参考原型：`AI智能库存研判交互原型.zip`

## 1. 目标

将参考原型中的库存研判与工单体系还原到现有 Demo，同时继续使用现有 V2 规则引擎、火山方舟 AI 研判、R2 状态、登录权限和工单闭环接口。参考原型只提供视觉和交互合同，Mock 数据不进入正式业务状态。

## 2. 还原范围

### 总部统一视觉系统

- 原型是总部 PC 端唯一视觉基准，不再在旧后台上追加另一层主题皮肤；
- 统一使用 220px 深蓝侧栏、52px 顶栏、橙色业务强调、8px 卡片圆角，以及同一套表格、标签、页签、弹窗和表单规格；
- `/` 运营总览、`/work-orders/` 跟进工单列表、`/diagnosis-v3/` 异常研判和 `/work-order/?portal=hq&id=...` 工单详情按原型重建；
- 盘点、订货、收货、调拨、库存单据、台账、流水、同步、通知、账号沿用同一全局壳层与组件规范，业务页面逐步消除局部旧样式；
- 原型中的 Mock 数字不进入系统，所有页面读取现有接口和真实 Demo 状态。

### 库存研判

- 深蓝色库存研判导航与橙色业务强调色；
- 当前问题、待验证、已关闭、历史观察四类视图；
- 一个持续问题对应多次营业日观察；
- 规则建议和 AI 建议明确区分“候选”“已采纳”；
- 创建工单前选择建议，完成创建后才写入正式工单。

### 工单详情

- 顶部展示规则、状态、SLA、负责人、门店、物料、首要研判；
- 展示理论库存、实物库存、原因证据状态和规则版本；
- 主内容使用五个页签：问题摘要、建议动作与执行、库存修正与验证、系统研判过程、业务记录；
- 右侧固定展示基础信息、关闭门禁、缺失证据和新增处理记录；
- 人工闭环使用弹层表单，保留重新打开、升级督导、升级总部和主数据治理能力。

### 持续问题业务不变量

视觉重建不得改变以下业务逻辑：

1. `门店 + 物料 + 单位 + 问题族` 构成持续问题基础键；同一问题跨营业日追加观察，不重复建立一张新问题单。
2. 案例保存首次营业日、最新营业日、首见/末见时间、观察次数和包含首尾两日的持续天数。
3. 每次 V2 自动或手动重算追加快照与决策轨迹，不覆盖首次研判。
4. 一个持续问题同一时间最多一张活动工单；工单关闭后同类信号再次触发，建立带 `recurrence_of_case_id` 的复发案例。
5. 当最新营业日不再触发，但尚未满足人工闭环条件时，进入“待验证”，不直接伪装成已关闭。
6. 工单必须保留来源研判、已采纳动作、业务单据、处理记录、修正前后库存和关闭门禁。

## 3. 数据映射

| 原型字段 | 现有数据来源 |
| --- | --- |
| 规则类型 | `diagnosis_v2.comparison.v2.rule_code` |
| 理论库存 | `fact_packet.quantities.theoretical_closing` |
| 实物库存 | `fact_packet.physical_count` |
| 首要原因 | `primary_location` / `primary_hypothesis` |
| 建议动作 | `inventoryCaseActions`，仅显示已采纳记录 |
| 首次及最新快照 | `diagnosis_runs` |
| 业务记录 | 工单关联单据、库存事件、审计记录 |
| 关闭门禁 | V2 最新状态、凭证、处理记录、最终结论 |
| 首次/最新营业日 | `opened_business_date` / `latest_business_date` |
| 持续时间 | `duration_business_days`，包含首尾营业日 |
| 观察次数 | `observation_count`，可展开查看每次观察 |
| 复发关系 | `recurrence_of_case_id` / `recurrence_index` |

## 4. 本轮实施

- `/`：重建为原型式运营总览；
- `/work-orders/`：新增正式工单列表，提供状态、规则、优先级、搜索和完整列信息；
- `/diagnosis-v3/`：应用参考原型视觉系统，保留真实持续问题与三步建单流程；
- `/work-order/?portal=hq&id=...`：改为参考原型的工单头部、五页签、右侧门禁和人工闭环弹窗；
- `app-shell.js` + `hq-prototype.css`：所有总部业务页面统一原型深蓝侧栏、顶栏与基础组件；
- 持续时间由研判领域层输出 `duration_business_days`，页面只负责展示，避免换页面时丢失口径；
- 所有执行按钮、重算、处理记录和人工闭环继续调用现有 API。

## 5. 后续还原

区域督导页和门店页继续保持各自的信息架构，不直接复制总部页面。涉及尚无真实数据的趋势、SLA、区域聚集和质量指标时，不直接照搬 Mock 数字，必须先标注模拟或补齐数据计算口径。

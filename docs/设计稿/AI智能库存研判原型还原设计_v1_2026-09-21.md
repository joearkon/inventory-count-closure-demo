# AI 智能库存研判原型还原设计 v1

日期：2026-09-21  
参考原型：`AI智能库存研判交互原型.zip`

## 1. 目标

将参考原型中的库存研判与工单体系还原到现有 Demo，同时继续使用现有 V2 规则引擎、火山方舟 AI 研判、R2 状态、登录权限和工单闭环接口。参考原型只提供视觉和交互合同，Mock 数据不进入正式业务状态。

## 2. 还原范围

### 库存研判

- 深蓝色库存研判导航与橙色业务强调色；
- 当前问题、待验证、已关闭、历史观察四类视图；
- 一个持续问题对应多次营业日观察；
- 规则建议和 AI 建议明确区分“候选”“已采纳”；
- 创建工单前选择建议，完成创建后才写入正式工单。

### 工单详情

- 顶部展示规则、状态、SLA、负责人、门店、物料、首要研判；
- 展示理论库存、实物库存、原因证据状态和规则版本；
- 主内容使用五个页签：问题摘要、建议动作与执行、库存修正与验证、系统研判过程、业务记录；
- 右侧固定展示基础信息、关闭门禁、缺失证据和新增处理记录；
- 人工闭环使用弹层表单，保留重新打开、升级督导、升级总部和主数据治理能力。

## 3. 数据映射

| 原型字段 | 现有数据来源 |
| --- | --- |
| 规则类型 | `diagnosis_v2.comparison.v2.rule_code` |
| 理论库存 | `fact_packet.quantities.theoretical_closing` |
| 实物库存 | `fact_packet.physical_count` |
| 首要原因 | `primary_location` / `primary_hypothesis` |
| 建议动作 | `inventoryCaseActions`，仅显示已采纳记录 |
| 首次及最新快照 | `diagnosis_runs` |
| 业务记录 | 工单关联单据、库存事件、审计记录 |
| 关闭门禁 | V2 最新状态、凭证、处理记录、最终结论 |

## 4. 本轮实施

- `/diagnosis-v3/`：应用参考原型视觉系统，保留真实持续问题与三步建单流程；
- `/work-order/`：改为参考原型的工单头部、五页签、右侧门禁结构；
- `app-shell.js`：仅在库存研判和工单页面启用参考原型深蓝侧栏，避免影响其他现有业务页面；
- 所有执行按钮、重算、处理记录和人工闭环继续调用现有 API。

## 5. 后续还原

总部运营总览、工单独立列表、区域督导页和门店页可继续按照同一视觉合同改造；涉及尚无真实数据的趋势、SLA、区域聚集和质量指标时，不直接照搬 Mock 数字，必须先标注模拟或补齐数据计算口径。

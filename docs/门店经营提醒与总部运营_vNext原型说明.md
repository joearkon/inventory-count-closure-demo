# 门店经营提醒与总部运营 vNext 原型说明

> 状态：独立交互原型，不连接业务接口，不进入现有导航，不部署线上
>
> 原型路径：`prototypes/operations-reminders-vnext/index.html`

## 1. 本轮验证的问题

原型按《总部运营与门店经营提醒 MVP 设计 v1》补齐门店、督导、总部三角色，但不验证视觉风格是否最终定稿，而验证以下产品假设：

1. 门店是否能在 3 秒内知道今天最重要的事情；
2. 普通提醒是否可以限制为 1～3 条，而不是展示所有异常；
3. LLM 是否能把规则和证据解释为门店愿意执行的动作；
4. 门店的“稍后提醒、与实际不符、需要帮助”是否能成为有效反馈；
5. 督导是否只接收门店求助、超时和连续未恢复事项；
6. 总部是否可以先看跨门店问题簇，再下钻独立工单；
7. 数据质量问题是否应与门店执行问题分开；
8. 提醒是否始终引用现有工单，而不是产生第二套业务状态；
9. 提醒已查看、工单处理中、V2 已恢复是否能被清楚地区分。

## 2. 门店端信息结构

门店端默认只展示三层：

```text
今天最重要：最多 1 条
需要你处理：普通提醒最多 3 条
今日经营简报：每天 1 条
```

“今天最重要”使用影响、紧迫、可执行性和可信度排序。高影响但门店无法处理的数据问题不推给门店，直接进入总部数据质量队列。

提醒卡不直接使用 D2、D1、S1、T2 等技术枚举，而显示：

- 发生了什么；
- 为什么值得今天处理；
- 系统核对过哪些证据；
- 建议先做什么；
- 处理后系统如何验证。

## 3. LLM 交互

点击“问门店助手”打开解释层。LLM 的输入必须来自冻结的结构化上下文：

- 当前工单；
- 最新 V2 结果；
- 证据与缺失证据；
- 可执行动作；
- 门店角色与语言；
- 规则和文案版本。

LLM 允许解释、追问、合并信息和预填草稿，不允许修改规则结论、自动提交单据、改变库存、自动定责或关闭工单。

## 4. 总部端信息结构

总部端用漏斗说明为什么没有展示所有信号：

```text
原始信号 → 合并问题 → 可执行事项 → 总部需介入
```

首页只保留四类内容：

1. 今日需干预；
2. 跨门店共性问题；
3. 执行与闭环；
4. 数据质量。

每个总部聚合问题引用若干独立门店工单。处理主数据或供应链问题后，对关联工单批量触发 V2 重算，但不直接批量关闭工单。

## 5. 督导端信息结构

督导不查看区域内所有门店提醒，只接收：

- 门店主动请求帮助；
- 门店超过 SLA 未行动；
- 连续两次重算仍未恢复；
- 多项风险叠加且需要现场复核。

督导提醒第一次需要介入时触达一次；只有 SLA 超时、优先级提升或 V2 结论变化才更新。系统同步失败、主数据缺失等门店无法解决的问题直接进入总部数据质量队列。

## 6. 与现有 Demo 的关系

保留现有：

- D2/D1/S1/T2 规则；
- V2 快照与历史；
- 跟进工单；
- 订货、收货、调拨、盘点和库存流水；
- 业务动作后的自动重算；
- 人工闭环、重开和升级门禁。

原型新增的是展示投影和交互，不新建平行数据源：

```text
现有异常与工单事实
→ 通知选择与优先级
→ 门店/督导/总部不同投影
→ 用户动作仍回到原工单和业务单据
```

## 7. 评审时需要拍板

1. 门店普通提醒上限是否采用每天 3 条；
2. “今天最重要”是否允许没有事项；
3. 门店可选择的反馈项；
4. 门店首页是否保留独立“提醒”Tab，还是并入“任务”；
5. 总部默认按区域、物料还是问题类型聚合；
6. 数据质量队列的责任角色；
7. LLM 解释是否默认展开；
8. 哪些情况允许立即推送飞书，哪些只进入日报。

## 8. 确认后的实现顺序

1. 冻结通知、受众和投递数据契约；
2. 给现有工单事件增加只读通知投影；
3. 实现门店提醒列表和详情；
4. 实现总部问题聚合与下钻；
5. 接入去重、抑制、SLA 与升级；
6. 最后将飞书作为统一提醒的投递通道；
7. 用 D2 主链和 D1/S1/T2 补充案例做保护测试。

## 9. 从 0 到 1 的门店习惯培养

不建议第一天就把全部提醒能力打开。建议按四个阶段推进：

| 阶段 | 门店看到什么 | 目标 | 进入下一阶段的条件 |
|---|---|---|---|
| 影子期 | 不主动推送，只由项目组查看候选提醒 | 校准误报、重复和角色归属 | 连续 7 天高优先级候选均可解释 |
| 第 1 周 | 只推明确待办与处理结果，每天普通提醒最多 1 条 | 建立“提醒能帮助我完成事情”的信任 | 门店能够完成查看、行动和反馈 |
| 第 2～3 周 | 增加每日经营简报，普通提醒最多 3 条 | 培养每天查看一次的习惯 | 无明显投诉，重复提醒受控 |
| 稳定期 | 接入销售、成本和订货建议，并按门店偏好调整 | 从执行提醒升级到经营助手 | 数据质量、采纳率和闭环率达标 |

门店提醒文案遵循：不责备、不使用技术枚举、一次只要求一个主要动作、说明系统已经核对的证据，并明确处理后如何验证。

## 10. 原型评估指标

第一阶段不以“发送数量”作为成功指标，建议观察：

- 门店首次行动时间；
- 门店完成率和按时完成率；
- “与实际不符”反馈率；
- 稍后提醒比例；
- 需要督导介入比例；
- V2 处理后恢复率；
- 同一事项重复触达次数；
- 门店主动打开经营简报的比例；
- 总部从聚合问题进入工单的比例；
- 数据质量问题被错误推给门店的数量。

这些指标用于调整提醒选择与文案，不用于自动评价个人绩效。

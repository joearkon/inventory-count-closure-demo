# 端到端验收场景清单 (E2E Acceptance Scenarios)

> 版本: v1 | 维护方: 飞书/豆包工作侧
> 适用: MVP 9/25 验收 + 后续每周回归
> 设计原则: **每个场景 = 1 个真实业务问题 → 1 分钟内 AI 给出归因/建议/操作**

---

## 设计理念

### 1 分钟归因的 5 要素

每个验收场景必须能跑通这 5 个环节：

```
1. 用户提问（自然语言）
   ↓
2. AI 在 1 分钟内（≤60s）响应
   ↓
3. 给出【判定 / 归因 / 建议】三段式输出
   ↓
4. 用户可一键执行建议动作（飞书卡片按钮 / AI 助手对话）
   ↓
5. 反馈闭环（动作结果回到系统，下次判定更准）
```

### 验收标准

| 维度 | 标准 |
|---|---|
| **响应时间** | ≤ 60 秒（含 LLM 调用） |
| **准确率** | ≥ 90% 的场景判定正确 |
| **覆盖度** | 5 类业务问题 × 2 角色 = 10 个场景全跑通 |
| **可执行性** | 90% 的建议有具体动作按钮 |

## 场景 1：加盟商 · 今日销量诊断

**触发 query（自然语言）**：
> "我今天的销量怎么样？"

**期望响应（≤ 60 秒）**：

```
hi 加盟商！👋

【今日销量诊断】（响应时间 1.8s）

📊 数据快照（截止 14:30）
• 今日销量：127 杯（昨日同期：185 杯，-31%）
• 7 日均量：168 杯/天
• 当前小时段（14:00-15:00）：8 杯（昨日同期：22 杯）

🔍 归因分析
你的销量在下午时段明显下滑，可能原因：
1. ⓐ 天气（今日 35°C 暴雨，下午时段客流下降）
2. ⓑ 竞品（隔壁新开的茶饮店在做 5 元试饮）
3. ⓒ 你的门店物料情况（杯盖库存 5 天，建议关注）

💡 建议操作
1. [生成下午时段促销方案] — AI 助手一键生成
2. [查看杯盖补货] — 跳转 AI 助手补货对话
3. [忽略此提醒] — 24h 不再推送

[按钮：生成促销方案] [按钮：杯盖补货] [按钮：忽略]
```

**验收标准**：
- [ ] 响应时间 ≤ 60s
- [ ] 含 3 个数据点（今日 / 昨日 / 7 日均量）
- [ ] 归因至少 2 个可能原因
- [ ] 至少 1 个可执行按钮
- [ ] 数据来源标注（Base 表名）

## 跨场景通用验收

每个场景都必须满足：

| 维度 | 标准 | 检测方式 |
|---|---|---|
| **响应时间** | ≤ 60s | 压测 100 次取 P95 |
| **数据准确性** | 与 Base 数据 100% 一致 | 取 5 条关键数据人工核对 |
| **三语切换** | zh-CN / en-US / id-ID 都正确 | 每语跑 1 遍 |
| **飞书卡片** | 按钮可点击 / 跳转正确 | 用户实测 |
| **门店隔离** | A 店看不到 B 店数据 | 权限测试 |
| **离线降级** | Base 不可达时不崩溃 | 压测 |

## 测试执行流程

### 9/25 MVP 验收日

1. **环境准备**：Base mock 数据灌入 / 飞书 bot 在线 / HTML App 可访问
2. **场景 1-5**（加盟商视角）：每个场景跑 1 遍，记录响应时间 + 内容准确度
3. **场景 6-10**（总部视角）：每个场景跑 1 遍
4. **跨场景通用**：三语切换 + 权限隔离 + 离线降级各跑 1 遍
5. **汇总报告**：
   - 10 个场景响应时间表
   - 准确度打分（每场景 0-100）

- 10 个场景全部跑通不报错
- 8/10 个场景准确度 ≥ 90%
- 响应时间 P95 ≤ 60s
- 三语切换 100% 正确

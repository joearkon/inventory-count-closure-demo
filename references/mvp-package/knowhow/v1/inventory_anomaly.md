## 1. 库存异常的本质

### 1.1 什么是"库存异常"

库存异常 = 理论库存与实盘库存/应有库存之间的偏差，且偏差超出该物料类型的合理损耗阈值。

**三类异常**：
1. **方向异常（D2）**：库存方向反了——负库存 = 数据流断点；期末 = 0 但有销量 = 漏减库存
2. **量级异常（D1）**：库存数量级错了——理论与实盘差异超出阈值
3. **结构异常（S1 / T2）**：库存结构错了——安全库存不足 / 销入比失衡

### 1.2 为什么必须分类型判定

不同物料的损耗特性差异巨大：

| 物料类型 | 合理偏差 | 典型异常表现 |
|---|---|---|
| 包装耗材（杯盖/吸管） | 0.5%-2% | 杯盖缺货导致断货 |
| 易耗液体（糖浆/果糖） | 1%-3% | 漏记入库 / 偷盗 |
| 现制半成品（半成品奶茶） | 3%-8% | 配方录入错误 / 制作残余 |
| 自然损耗（鲜果/鲜茶叶） | 10%-20% | 鲜度问题 / 订货过量 |
| 称重原料（黑糖珍珠） | 0.5%-2% | 称重误差 / 包装破损 |
| 一般物料（清洁剂） | 0% | 极少异常 |

**不分类型 = 误报泛滥**。一杯奶茶店里，"鲜果损耗 15%"是合理的，"吸管损耗 15%"就是大问题。

## 2. 5 档研判输出

### 2.1 五档定义

| 档位 | 中文 | 含义 | 是否需要人工 |
|---|---|---|---|
| **有证据** | confirmed | 已有确凿证据，可直接定责 | 自动推送 + 加盟商执行 |
| **已排除** | excluded | 已检查所有可能源，未发现异常 | 仅归档，无需人工 |
| **疑似** | suspect | 部分证据但不能定责，需人工核查 | 督导 / 加盟商介入 |
| **证据不足** | insufficient | 缺关键数据（盘点/入库/配方），需补录 | 加盟商补录 / 系统重跑 |
| **待盘点** | pending_count | 判定需实盘数据，等待下次盘点 | 仅监控，下次盘点后重判 |

### 2.2 MVP 不自动定责原则

参考 Crunchtime、RestoSuite 等海外成熟餐饮 AI 系统的做法：
- **AI 给判定和建议，人做最终决定**
- MVP 不调用 LLM 自动定责到个人，只到"门店级 / 物料级"
- 加盟商看到的是"这个物料有疑似异常，可能原因 1/2/3，建议操作 1/2/3"

### 2.3 五档之间的升级路径

```
insufficient  → 补录数据 → 重判定
pending_count → 下次盘点  → 自动重判
suspect       → 督导 24h 内复核 → 升级到 confirmed 或 excluded
confirmed     → 加盟商/督导执行 → 反馈回系统
excluded      → 归档，下一轮继续监控
```

## 3. 四类硬规则详解

### 3.1 D2 负库存与异常方向

**触发条件**：期末 < 0 OR 期末 = 0 AND 销量 > 0 OR 期末 > 安全库存 × 10

**判定优先级**（由高到低）：
1. 期末 < 0 → **confirmed**（一定有数据或流程异常）
2. 期末 = 0 AND 销量 > 0 → **confirmed**（卖出 0 库存 = 漏减）
3. 期末 > 安全库存 × 10 → **confirmed**（入库过量）
4. 流水中无冲销/红冲 → **excluded**（已正确处理）
5. 数据同步延迟 < 30 分钟 → **insufficient**（等待同步）

**Fallback**：suspect（人工核查）

### 3.2 D1 理论与实盘差异

**触发条件**：ABS(理论期末 - 实盘) > 阈值（按物料类型 0.5%-10%）

**关键点**：
- 理论期末 = 期初 + 入库量 - 今日消耗 - 报损量
- 实盘数据来源于周盘点
- **物料类型决定阈值**（见附录 C threshold_table.json）

**判定步骤**：
1. 理论期末 < 0 → **confirmed**（物耗公式或配方错）
2. 差异 > 阈值 × 2 → **confirmed**（现场核查）
3. 近 7 日有调拨 → **suspect**（查调拨单）
4. 近 7 日有报损 → **excluded**（报损已记录）
5. 配方最近改过 → **suspect**（复核配方）

### 3.3 S1 安全库存预警

**触发条件**：期末 < 安全库存相关阈值

**物料类型决定响应速度**：
- 包装耗材 / 易耗液体 → critical，4h 内补货
- 现制半成品 → warning，8h 内补货
- 自然损耗 / 称重原料 → warning，24h 内补货
- 一般物料 → info，48h 内补货即可

**注意**：安全库存设置需考虑物料的订货前置时间 + 周转天数 + 季节性波动

### 3.4 T2 销入比异常

**销入比 = 7 日销量 / 7 日入库量**

**异常方向**：
- 销入比 > 3.0 → **confirmed**（疑似漏记入库 / 销量虚高）
- 销入比 < 0.3 → **suspect**（积压 / 销量骤降 / 入库过量）
- 销入比 0.3 ~ 2.5 → 正常区间

**易误报场景**：
- 新 SKU 上线（库存爬坡期）
- 老 SKU 下线（库存清理期）
- 促销期间（销量激增）
- 季节性低销期

## 4. 异常归因 6 大根因

每条异常都需要回答"为什么"。MVP 第一版归因分类：

### 4.1 数据录入错误（占预计异常的 35%）

- 入库数量录错（多打一个 0）
- 销售数量漏录或重复录
- 配方录入错误（物料配比反了）
- 单据号填错

**识别信号**：通常单条数据异常，其他正常

### 4.2 单据流转断点（占预计异常的 25%）

- 入库单已入库但未同步到台账
- 调拨单已发出但未确认收货
- 报损单已审批但未扣库存

**识别信号**：跨表数据不一致

### 4.3 物理损耗超标（占预计异常的 20%）

- 制作损耗（半成品残余）
- 鲜度损耗（鲜果过期）
- 操作损耗（洒漏、破损）
- 称重误差（黑糖珍珠克数偏差）

**识别信号**：与历史损耗率比对，超出 1.5 倍

### 4.4 偷盗 / 内盗（占预计异常的 10%）

- 物料被员工私自带走
- 现金销售未入账（伴生现象）

**识别信号**：连续多日小差异、晚班时段异常

### 4.5 顾客行为（占预计异常的 5%）

- 退单未扣库存
- 赠饮未记录
- 自带杯优惠

**识别信号**：差异方向与销售时段一致

### 4.6 系统 / 流程问题（占预计异常的 5%）

- 数据同步延迟
- 表结构变更未通知
- 配方版本不一致

**识别信号**：多门店同时出现类似异常

## 5. 异常处理 SLA

按严重程度分级：

| 严重程度 | SLA | 升级路径 |
|---|---|---|
| critical（D2 负库存 / S1 关键物料断货） | 1-4 小时 | 加盟商 → 督导 → 总部 |
| warning（D1 差异 / S1 半成品预警 / T2 销入比异常） | 12-24 小时 | 加盟商 → 督导 |
| info（S1 一般物料 / T2 环比异动） | 48 小时 | 加盟商 |

**超时 2 次**：标记为高风险门店，进入复诊跟踪

## 6. MVP 落地建议

### 6.1 第一周（运营期前 4 周）

- **保守拍板阈值**（偏紧）：宁可误报也不要漏报
- **5 档输出全部跑通**：重点验证 confirmed/excluded 两档准确度
- **收集误报案例**：每周汇总，10/23 拍板 v2 阈值

### 6.2 第二阶段（运营期 5-8 周）

- **阈值校准**：基于 4 周真实数据
- **归因模型升级**：从 6 大根因精细化到 12 类
- **自动化推送**：把 confirmed 档的响应时间从 SLA 内压到 SLA 的 50%

### 6.3 第三阶段（8 周后）

- **跨门店模式识别**：识别加盟商层面的系统性问题
- **预测性预警**：从"已发生的异常"升级到"将要发生的异常"
- **自动调拨建议**：基于历史销量和库存周转，给出调拨方案

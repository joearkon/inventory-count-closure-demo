## 3. 加盟商运营诊断 KPI 体系

参考海外成熟连锁（7-Eleven、麦当劳、星巴克）的 KPI 体系：

### 3.1 经营 KPI（5 个）

1. **日均销量**（核心）
2. **毛利率**
3. **库存周转天数**
4. **复购率**（Phase 2 CRM 接入）
5. **客诉率**（Phase 2 客服系统接入）

### 3.2 运营 KPI（8 个）

1. 物料损耗率（按类型）
2. 安全库存达标率
3. 盘点准确性
4. 单据完整率
5. 配方一致率
6. 报损及时率
7. 调拨执行率
8. 培训完成率

### 3.3 总部 KPI（4 个）

1. 加盟商诊断覆盖率
2. 异常响应及时率
3. 复诊完成率
4. 异常复发率

## 4. AI 诊断在餐饮业的应用现状

### 4.1 已成熟的应用

- **销量预测**：基于历史 + 天气 + 节假日的销量预测，准确率 85%+
- **自动订货**：基于销量的物料补货建议
- **损耗分析**：识别异常损耗的物料和时段
- **菜品分析**：基于 POS 的爆款 / 滞销菜品识别
- **AI 巡检**：基于摄像头视频分析的违规行为识别（InfiSight）

### 4.2 还在探索的应用

- **加盟商诊断报告**：自动生成经营分析（这是我们要做的）
- **配方优化**：基于成本和销量的配方建议
- **选址分析**：基于人流和商圈的销售预测
- **顾客流失预警**：基于消费频次的预警

### 4.3 行业共识与差异

**共识**：AI 用于"识别和提示"，人做"判断和执行"

**差异**：
- 国内方案偏"全自动化"（减少人力）
- 国际方案偏"辅助决策"（保留人的判断）
- 我们选"辅助决策"路线——更符合加盟商关系（不是总部 vs 加盟商，是合作伙伴）

## 5. RAG 在餐饮业知识管理的应用

### 5.1 知识库的常见来源

- 行业 knowhow（类似本文档）
- 加盟商操作手册
- SOP（标准操作流程）
- 异常案例库
- 历史诊断报告

### 5.2 RAG 检索的关键设计

- **chunk 切分**：按"问题 + 答案"切分最有效
- **Embedding 模型**：中文用 BGE / M3E，英文用 OpenAI
- **混合检索**：BM25 + 向量检索 + rerank
- **命中率目标**：≥ 85%

### 5.3 我们的 RAG 设计原则

- **冷启动友好**：4 份 MD + 4 份 JSON = 足够启动
- **可热更新**：阈值表 / 决策树支持在线更新（运营期校准）
- **多语言**：中英文为主，印尼语 MVP 不要求

## 6. MVP 落地的行业参考建议

### 6.1 借鉴点

| 来源 | 借鉴点 | 我们怎么做 |
|---|---|---|
| Crunchtime | Food cost 精细化 | 6 类物料分类 + 损耗率基线 |
| InfiSight | AI 自动巡检 | AI 诊断 + 自动推送 |
| 美团数智督导 | 督导工作流 | 16 条响应动作 + SLA 分级 |
| 7-Eleven | KPI 体系 | 5+8+4 = 17 个 KPI |
| Toast POS | 一体化体验 | HTML App + AI 助手一体化 |

### 6.2 差异点（避免踩坑）

- **不直接抄 Crunchtime 的"总部集权"模式**——加盟商关系不同
- **不做视频分析**——MVP 阶段数据不够（无视频流）
- **不做菜品分析**——MVP 阶段聚焦库存/物料
- **不做选址/CRM**——Phase 2 再考虑

## 1. 门店运营异常的本质

### 1.1 什么是"门店运营异常"

门店运营异常 = 门店在 **销售、盘点、客流、服务、财务** 五个维度的指标偏离该门店历史基线 + 同期同型门店基线，且偏离超出合理波动范围。

**五大维度异常**：
1. **销售异常（S1）**：日销量 / 周销量 / 月销量连续低于基线（市场不好 vs 我不好）
2. **盘点异常（S2）**：盘点缺失 / 盘点偏差 / 盘点异常率超阈值
3. **客流异常（S3）**：日客流 / 时段客流连续下滑
4. **客单异常（S4）**：客单价连续下滑 / 异常偏低
5. **服务/财务异常（S5）**：退货率 / 客诉 / 毛利率异常

### 1.2 为什么不能只看销售增长（LTV/MAU 模型陷阱）

茶饮加盟门店单看销售会**误判**：
- **销量增长但毛利下滑** = 促销活动过度，门店可能在赔钱赚吆喝
- **销量稳定但客流下滑** = 老客在流失，结构性问题
- **销量增长但退货率上升** = 服务质量下滑，口碑正在崩塌

**判断门店好不好，不能只看一个指标**。要分维度、分时间窗、分场景。

### 1.3 异常判定的时间维度（关键）

| 时间窗 | 适用判定 | 灵敏度 |
|---|---|---|
| **日内（小时）** | 实时预警（库存断货 / 时段销售异常） | 高 |
| **近 3 日** | 短期异常（连续低销 / 异常率累计） | 中（推荐 MVP 起步） |
| **近 7 日** | 周趋势（是否与上周同比下滑 > X%）| 中 |
| **近 30 日** | 月趋势（季节性 / 结构性问题） | 低 |

**MVP 默认 3 日窗口** —— 加盟商反应够快，总部 24h 内有信号。

## 2. 5 档研判输出

（与库存异常判定手册 v1 对齐）

| 档位 | 中文 | 含义 | 是否需要人工 |
|---|---|---|---|
| **有证据** | confirmed | 已有确凿证据，可直接定责 | 自动推送 + 加盟商执行 |
| **已排除** | excluded | 已检查所有可能源，未发现异常 | 仅归档，无需人工 |
| **疑似** | suspect | 部分证据但不能定责，需人工核查 | 督导 / 加盟商介入 |
| **证据不足** | insufficient | 缺关键数据（盘点/客流/会员），需补录 | 加盟商补录 / 系统重跑 |
| **待观察** | pending | 判定需更多数据，等待下次同步 | 仅监控，下次同步后重判 |

**MVP 启动后**：加盟商看到的是"你今天的销售比昨天低 X%，可能原因 1/2/3，建议操作 1/2/3"，督导看到的是"该门店连续 3 天销售下滑，需复核"。

## 3. 五大维度硬规则详解

### 3.1 S1 销售异常（核心场景）

#### 触发场景
- **连续低销**：近 3 日销售量 < 历史同期基线 70%（连续 3 天）
- **周环比下滑**：本周销量 < 上周同期 80%
- **月环比下滑**：本月销量 < 上月同期 70%（剔除节假日）

#### 判定优先级
1. **门店全店关闭**（装修 / 春节）→ **excluded**（业务原因）
2. **同期同型门店平均销量也低** → **excluded**（市场原因，非该门店问题）
3. **该门店客流 < 同期 70%** → **confirmed**（人流问题）
4. **客流正常但客单价 < 同期 80%** → **confirmed**（产品/促销问题）
5. **客流 + 客单都正常** → **suspect**（看 SKU 级别，可能某个 SKU 断货）
6. **数据延迟 < 30 分钟** → **insufficient**（等待同步）

#### 行业基准（茶饮加盟）
- 优秀门店：日销 > 同期同型 + 30%
- 正常门店：日销 = 同期同型 ±20%
- 关注门店：日销 = 同期同型 -20% ~ -40%
- 异常门店：日销 < 同期同型 -40%
- 单店日销骤降 ≥ 40% 且持续 3 天 → **必报**

#### 数据需求
- 销售明细（按门店 + SKU + 时间段）
- 同期同型门店的销量聚合
- 门店营业状态（是否正常营业）

#### 推荐响应动作
| 档位 | 门店收到 | 督导收到 | 总部收到 |
|---|---|---|---|
| confirmed | "你今天客流跌了 30%，建议明天主推 X" | "XX 门店客流异常，复核活动/位置" | 区域风险列表加入 XX 门店 |
| suspect | "你 SKU X 库存为 0，建议补货或换 SKU" | "XX 门店 SKU X 断货风险" | — |

---

### 3.2 S2 盘点异常（核心场景）

#### 触发场景
- **盘点缺失**：连续 3 日无盘点记录
- **盘点差异**：单次盘点偏差 > 该类物料合理偏差阈值（如吸管 > 2%）
- **盘点异常率高**：盘点异常次数 / 盘点总次数 > 30%（如 10 次盘点有 3 次异常）

#### 判定优先级
1. **盘点当日闭店 / 停业** → **excluded**（业务原因）
2. **盘点缺失 = 节假日（如春节 7 天）** → **excluded**
3. **盘点差异 ≤ 物料类型合理阈值** → **excluded**
4. **盘点差异 > 阈值但 < 2 倍阈值** → **suspect**（需督导复核）
5. **盘点差异 > 2 倍阈值** → **confirmed**（立即派人）
6. **连续 3 日无盘点** → **insufficient**（提醒门店补盘）

#### 行业基准（茶饮加盟）
- **每日盘点**：理想做法，但实际成本高（每次 30 分钟）
- **每周盘点**：行业标准（一般周末营业前）
- **连续 3 日无盘点**：MVP 必报阈值（3 日 > 周中段开始就有问题）
- **连续 7 日无盘点**：必须派人现场协助

#### 推荐响应动作
| 档位 | 门店收到 | 督导收到 | 总部收到 |
|---|---|---|---|
| confirmed | "你的盘点差异 5%，远超阈值 2%，请检查" | "XX 门店需现场盘点协助" | 区域盘点异常列表置顶 |
| insufficient | "提醒：你已 3 天没盘点，今天务必补盘" | "XX 门店盘点缺失超 3 天" | — |

---

### 3.3 S3 客流异常

#### 触发场景
- **日客流下滑**：日客流 < 同期 70%（连续 3 日）
- **时段客流异常**：午高峰客流 < 同期 50%
- **客流骤降**：单日客流 < 50%（短期事件，如天气 / 周边施工）

#### 判定优先级
1. **周边施工 / 道路封闭** → **excluded**
2. **极端天气（台风 / 暴雨）** → **excluded**
3. **节假日效应**（如春节假期整体客流低）→ **excluded**
4. **同期同型门店客流也低** → **excluded**（市场原因）
5. **单店客流 < 同期 70% 持续 3 日** → **confirmed**
6. **客流骤降 < 50%** → **suspect**（需立即现场核查）

#### 数据需求
- 客流数据（POS 收银次数 / 摄像头客流 / 第三方平台）
- 同期同型门店客流
- 节假日 / 天气标注

---

### 3.4 S4 客单价异常

#### 触发场景
- **客单价连续下滑**：客单价 < 同期 80%（连续 3 日）
- **客单价异常偏低**：客单价 < 同型门店 -30%
- **客单价突增**：客单价 > 同期 +50%（可能是大单 / 团购，需排除）

#### 判定优先级
1. **大单效应**（如 10 杯订单）→ **excluded**（业务原因）
2. **促销活动**（全场 5 折）→ **excluded**（明示活动）
3. **新 SKU 上市**（拉低平均价）→ **excluded**（短期波动）
4. **客单价 < 同期 80% 持续 3 日** → **confirmed**（结构性问题）

#### 推荐响应动作
- **confirmed**："你客单价跌了 20%，建议推 X / Y 高客单 SKU"

---

### 3.5 S5 服务/财务异常

#### 触发场景
- **退货率高**：退货订单 / 总订单 > 5%（连续 3 日）
- **客诉频次**：客诉数 > 3 次/周
- **毛利率异常**：月度毛利 < 50%（偏离基线 > 10%）

#### 判定优先级
- 退货率 > 5% 持续 3 日 → **suspect**
- 客诉 > 3 次/周 → **confirmed**（高优）
- 毛利率 < 50% 且与同期差距 > 10% → **confirmed**（财务红线）

## 4. 异常优先级矩阵

```
                  影响范围小        影响范围大
                  （单店）         （多店/全网）
紧急性高 ───────  confirmed       confirmed  → 督导介入
紧急性中 ───────  suspect         confirmed  → 区域介入
紧急性低 ───────  suspect         suspect    → 月度盘点
```

## 6. 与库存异常的关系

| 关系 | 说明 |
|---|---|
| **互斥** | 库存异常聚焦"物料维度"，门店异常聚焦"门店维度"。同一条数据在两个维度都看 |
| **互补** | 库存异常通常反映"物料供应链"，门店异常反映"门店运营"。两者结合 = 完整归因 |
| **联动** | 当门店异常（S1/S4）伴随库存异常（D2/S1）→ 是确认归因的关键信号 |

**经典联动案例**：
- 门店 S1 销售下滑 + 库存 S1 安全库存不足 → **根因是断货，需补货**
- 门店 S4 客单价下滑 + 库存 D2 负库存 → **根因是高客单 SKU 卖完了，需调整菜单**

## 7. 局限与边界

### 7.1 MVP 不做的判定

- **不判定员工行为**（出库时间异常、多次取消订单）—— 需更细粒度数据，V2 再做
- **不判定供应链上游**（供应商断货 / 物流延迟）—— 需供应商数据，V2 再做
- **不判定口味 / 产品质量**—— AI 难以判定，需人工 / 客户反馈，V2 再做

### 7.2 MVP 误报缓解

- 同期同型门店过滤：单店异常 vs 整体异常分离
- 节假日 / 天气过滤：标注已知外部因素
- 督导复核机制：suspect 档 24h 内必须复核
- 月度校准：每月底根据督导反馈调整阈值

### 7.3 必报 vs 参考

| 触发 | MVP 推送 | 督导介入 |
|---|---|---|
| 连续 3 日异常 + confirmed | ✅ 立即推送 | ✅ 24h 内复核 |
| 单日异常 | 仅展示，不推送 | ❌ |
| 周累计异常 | ✅ 周报 | ❌ |

## 8. 术语表

| 术语 | 定义 |
|---|---|
| 同期 | 同比去年同期同月同期日 |
| 同型门店 | 同一商圈类型 + 同一规模 + 同一开业时长 |
| 基线 | 该门店近 30 天的滚动平均 |
| 合理偏差 | 该物料类型在行业内的标准偏差范围 |
| 异常率 | 异常次数 / 总次数 |
| 督导 | 区域督导，负责区域门店巡检与辅导 |

## ST-1: 近 3 日销售量连续低

### 触发条件
```
触发方: 系统自动
触发时间: 每日 22:00
判定: 连续 3 日销售量 < 同期同型基线 70%
排除: 节假日 / 同期同型也低 / 门店停业
```

### 期望响应（≤60 秒）

**门店端推送**：
```
📉 销售下滑预警

【MM0005-MM-SANGGIANG】
近 3 日销售对比同期下滑 35%（同期 ¥4,500，今天 ¥2,930）

🔍 可能原因：
1. 客流下滑（同期 -28%）
2. 客单价稳定（同期 +2%）

✅ 建议操作：
1. 明天推 X SKU（高复购）
2. 检查会员召回
3. 9/20 督导现场复核

[我知道了]  [安排督导]
```

**督导端推送**：
```
🔔 门店预警：MM0005-MM-SANGGIANG

类型: 销售连续下滑（3 日）
下滑幅度: 35%
建议: 9/20 现场复核 + 客流原因诊断

[查看详情]  [派单]  [已处理]
```

**总部端列表**：
- 区域风险列表新增 MM0005-MM-SANGGIANG
- 推送状态：待确认 / 督导介入中

### 验证标准
- [ ] 推送时间 ≤ 60 秒
- [ ] 文案包含数字 + 可能原因 + 建议
- [ ] 一键操作按钮可点击
- [ ] 门店确认 → 督导看到状态
- [ ] 督导派单 → 总部看到状态

## ST-2: 近 3 日未盘点

### 触发条件
```
触发方: 系统自动
触发时间: 每日 22:00
判定: 连续 3 日无盘点记录
排除: 节假日 / 门店停业
```

### 期望响应（≤30 秒）

**门店端推送**：
```
⏰ 盘点提醒

【MM0005-MM-SANGGIANG】
你已连续 3 日未盘点（9/15、9/16、9/17）

⚠️ 风险：
- 库存数据可能偏离实际
- 明日总部盘点异常将无法溯源

✅ 建议：今晚 22:30 前补盘

[立即盘点]  [延期盘点]  [关闭]
```

**督导端**：
```
📋 盘点缺失：MM0005-MM-SANGGIANG（3 日）
```

### 验证标准
- [ ] 推送时间 ≤ 30 秒（轻量提醒，响应更快）
- [ ] 文案包含连续天数 + 风险 + 建议
- [ ] 一键操作可执行（盘点链接 / 延期）
- [ ] 门店补盘后，督导看到状态变化

## ST-3: 盘点异常率非常高

### 触发条件
```
触发方: 系统自动
触发时间: 每次盘点完成后
判定: 近 7 日盘点异常次数 / 总次数 > 30%
排除: 新店开业首月
```

### 期望响应（≤60 秒）

**督导端推送**：
```
🔍 盘点异常率高：MM0005-MM-SANGGIANG

近 7 日盘点异常率：42%（3/7 次异常）

📊 异常明细：
- 9/15 吸管 -8%（阈值 2%）
- 9/16 糖浆 -6%（阈值 3%）
- 9/17 杯子 -5%（阈值 2%）

🔍 可能原因：
1. 称重/计量不准
2. 制作流程损耗过高
3. 员工操作不规范

✅ 建议操作：
1. 9/20 现场复核
2. 重新培训员工
3. 检查计量器具

[派单]  [详情]  [已处理]
```

**门店端**（间接）：
- 督导现场时通知门店

### 验证标准
- [ ] 推送时间 ≤ 60 秒
- [ ] 包含异常明细（物料 + 偏差 %）
- [ ] 异常率百分比准确（mock 验证）
- [ ] 督导可一键派单

## ST-4: 客单价连续下滑

### 触发条件
```
触发方: 系统自动
触发时间: 每日 22:00
判定: 客单价 < 同期同型基线 80%，连续 3 日
排除: 促销活动 / 新 SKU 上市 / 大单效应
```

### 期望响应（≤60 秒）

**门店端推送**：
```
📉 客单价预警

【MM0005-MM-SANGGIANG】
近 3 日客单价 ¥15.8，对比同期 ¥20.5，下滑 23%

🔍 可能原因：
1. 高客单 SKU 销量下降（Black Sugar Boba +杯 -45%）
3. 复购主要走基础款

✅ 建议操作：
1. 主推 Black Sugar Boba +杯（客单 ¥25）
2. 推出 ¥28 套餐（含 +杯 + 小食）
3. 会员日主推 +杯系列

[了解]  [查看 SKU]  [已调整]
```

### 验证标准
- [ ] 推送时间 ≤ 60 秒
- [ ] 包含 SKU 级别的归因（哪个 SKU 拉低客单）
- [ ] 建议操作针对 SKU 而非全店
- [ ] 门店确认后状态同步督导

## ST-5: 退货率高 + 客诉

### 触发条件
```
触发方: 系统自动
触发时间: 每日 22:00
判定: 退货率 > 5% 持续 3 日 + 客诉 ≥ 1
排除: 促销活动导致的预期退货
```

### 期望响应（≤60 秒）

**督导端推送**（高优先级）：
```
🚨 服务质量预警：MM0005-MM-SANGGIANG

退货率：6.2%（近 3 日，阈值 5%）
客诉：2 件（本周）

📋 客诉明细：
- 9/15 "等待时间过长"（10:30 午高峰）
- 9/17 "冰沙太甜"

🔍 可能原因：
1. 午高峰人手不足（建议增加 1 人）
2. 配方标准不统一（建议重培训）

✅ 建议操作：
1. 9/18 现场复核
2. 检查午高峰排班
3. 培训冰沙制作标准

[立即派单]  [详情]  [已处理]
```

**总部端**（高优）：
- 区域风险列表置顶 + 红色标记

### 验证标准
- [ ] 推送时间 ≤ 60 秒
- [ ] 包含客诉明细（时间 + 描述）
- [ ] 督导必须 24h 内响应
- [ ] 总部看到红色高优标记

## 通用验证项（5 个场景都适用）

### 推送链路验证

- [ ] 督导端收到推送
- [ ] 总部端列表/卡片更新

- [ ] 督导标记「已处理」→ 门店看到感谢 + 总部列表移除

### 三语验证
- [ ] 中文 UI 正常
- [ ] 英文 UI 正常
- [ ] 印尼语 UI 正常

## 与库存场景（inv-1 ~ inv-10）的对比

| 维度 | 库存场景 | 门店场景 |
|---|---|---|
| 触发 | 库存数据流 | 销售 / 盘点 / 客流 / 客单 / 服务 |
| 推送对象 | 门店 + 督导 | 门店 + 督导 + 总部 |
| 响应时间 | ≤ 60 秒 | ≤ 60 秒（部分 ≤ 30 秒）|
| 闭环 | 加盟商执行 → 反馈 | 加盟商执行 → 督导复核 → 反馈 |

**两个 knowhow 共同覆盖 5 + 4 = 9 大维度**，组成完整的「门店 + 库存」双轨诊断体系。

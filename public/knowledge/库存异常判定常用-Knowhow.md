## 一、前言

### 1\.1 为什么需要这份手册

库存异常不是「有没有货」这么简单。对茶饮/F\&B 行业而言，库存异常意味着：钱卡在货里、货在过期、门店在断货、总部在背锅。一份统一、可执行的判定规则，是让系统代替人「天天盘账」的前提。

### 1\.2 适用范围

- **品牌类型**：茶饮、咖啡、轻食等连锁 F\&B 品牌

- **门店形态**：直营店、加盟店、前置仓、区域中心

- **数据基础**：已接入销售 POS、入库单、盘点表、报损单、调拨单五类单据

## 二、库存异常类型体系

### 2\.1 按异常性质分类（五维框架）

所有库存异常可归入以下五个维度。系统每次检测到异常时，应同时标注「维度 \+ 严重程度 \+ 物料 \+ 门店」。

|维度|异常名称|通俗解释|典型损失|
|---|---|---|---|
|**数量异常**|缺货 / 积压|该有货时没有，不该有货时一堆|断货损失营收 / 积压损失资金\+报废|
|**质量异常**|临期 / 变质 / 破损|货还在，但快不能用了|报废损失|
|**时序异常**|周转过慢 / 销入失衡|进货节奏与销售节奏不匹配|资金占用 / 断货|
|**结构异常**|SKU 结构失衡|热销品缺、滞销品多|机会成本|
|**数据异常**|理论 vs 实际差异|系统算出来的和实际对不上|决策失真|

### 2\.2 按严重程度分级（三色灯）

与系统「物料健康度矩阵」对齐，所有异常统一用三级颜色标记：

|等级|颜色|含义|响应时效|
|---|---|---|---|
|**预警**|🔴|已触发风险阈值，必须立即行动|4 小时内响应|
|**关注**|🟡|接近阈值或存在趋势性偏离，需要关注|24 小时内确认|
|**正常**|🟢|在合理区间内，无需干预|常规监控|

> **关键原则**：🔴 必须对应一条可执行动作，不能只标红不给方案。

## 三、异常判定规则（核心章节）

### 3\.1 安全库存类规则

#### 规则 S1：安全库存预警

**判定逻辑**：期末库存 \< 安全库存

**参数说明**：

- **安全库存** = 日均消耗 × 安全库存天数

- **安全库存天数** = 补货周期 \+ 缓冲天数

- 缓冲天数默认 1\-2 天（应对销量突增或物流延迟）

**茶饮行业安全库存天数参考**：

|品类|建议天数|理由|
|---|---|---|
|茶叶|15\-30 天|保质期长（12\-24 个月），消耗稳定|
|乳制品/奶基底|3\-7 天|保质期短（7\-15 天），需高频补货|
|果浆（冷冻）|7\-15 天|保质期长但需 \-18℃ 储存，补货链路长|
|鲜果|2\-4 天|保质期极短（3\-7 天），损耗风险高|
|糖浆|15\-30 天|保质期长（6\-12 个月），消耗稳定|
|小料（干）|15\-30 天|保质期长（6\-18 个月）|
|包材|15\-30 天|无保质期限制，可适量多备|

**响应动作**：

- 🔴 立即触发补货提醒，推送「立即订货」按钮

- 🟡 可用天数 ≤ 安全天数 × 1\.5 时，推送「建议关注」

**排查决策树**：

```
步骤 1：判断触发原因
  ├─ 库存确实不足（期末 < 安全库存，且无异常数据）
  │   └─ 检查近 7 日销量是否突增
  │       ├─ 是 → 销售上涨，需紧急补货 + 上调安全库存
  │       │     【系统动作】
  │       │     1. 自动推送「紧急补货提醒」至门店群 + 私聊店长
  │       │     2. 生成建议订货量 = 安全库存 × 1.5 − 期末库存
  │       │     3. 同步推送总部采购群，标记「销量突增门店」
  │       │     4. 记录异常根因为「销售上涨」，写入库存流水备注
  │       │
  │       └─ 否 → 进入步骤 2
  │
  └─ 库存数据异常（期末显示不足，但可能有未录入的到货）
      └─ 检查近 3 日是否有入库单未录入
      │   ├─ 是 → 【根因：收货未录】
      │   │     【系统动作】
      │   │     1. 自动推送「待收货提醒」至门店群，@店长
      │   │     2. 附带近 3 日到货物流单号，要求门店确认签收并录入
      │   │     3. 24h 未确认自动升级，推送总部运营群
      │   │     4. 记录异常根因为「收货未录」
      │   │
      │   └─ 否 → 检查是否有在途调拨未签收
      │       ├─ 是 → 【根因：在途调拨未签收】
      │       │     【系统动作】
      │       │     1. 自动推送「调拨待签收提醒」至门店群
      │       │     2. 附带调拨单号 DB-YYYYMMDD-NNN，要求确认
      │       │     3. 记录异常根因为「调拨未签收」
      │       │
      │       └─ 否 → 进入步骤 2

步骤 2：判断是否为系统性缺货
  ├─ 多门店同时触发同一物料安全库存预警 → 【总部责任】
  │   └─ 检查总部供货是否延迟
  │   │   ├─ 是 → 【根因：总部供货延迟】
  │   │   │     【系统动作】
  │   │   │     1. 自动推送「供货延迟预警」至总部采购群
  │   │   │     2. 附带受影响门店清单，标记物料 + 缺口数量
  │   │   │     3. 生成紧急采购建议，推送采购负责人
  │   │   │     4. 记录异常根因为「总部供货延迟」
  │   │   │
  │   │   └─ 否 → 检查安全库存天数设置是否过低
  │   │       ├─ 是 → 【根因：安全库存设置过低】
  │   │       │     【系统动作】
  │   │       │     1. 自动推送「配置调整建议」至总部运营群
  │   │       │     2. 附带当前设置 vs 建议设置对比
  │   │       │     3. 触发「库存配置表」更新审批流（待总部确认后生效）
  │   │       │     4. 记录异常根因为「安全库存配置偏低」
  │   │       │
  │   │       └─ 否 → 检查供应商履约率是否下降
  │   │           ├─ 是 → 【根因：供应商履约下降】
  │   │           │     【系统动作】
  │   │           │     1. 自动推送「供应商履约预警」至采购群
  │   │           │     2. 附带供应商近 30 天履约率数据
  │   │           │     3. 触发供应商评估工单，分配给采购负责人
  │   │           │     4. 记录异常根因为「供应商履约下降」
  │   │           │
  │   │           └─ 否 → 【根因：未知，需人工介入】
  │   │                 【系统动作】
  │   │                 1. 自动生成「异常调查工单」，分配给区域运营
  │   │                 2. 附带该物料全门店库存快照
  │   │                 3. 标记为「待人工归因」
  │   │
  └─ 仅单店触发 → 【加盟商动作】
      └─ 检查该门店订货频率是否合理
      │   ├─ 否 → 【根因：订货频率过低】
      │   │     【系统动作】
      │   │     1. 自动推送「订货频率建议」至门店群
      │   │     2. 附带建议订货周期（如从每周 1 次改为每周 2 次）
      │   │     3. 记录异常根因为「订货频率不足」
      │   │
      │   └─ 是 → 检查该门店销量是否异常高于同加盟商其他店
      │       ├─ 是 → 【根因：单店销量异常高】
      │       │     【系统动作】
      │       │     1. 自动推送「销量异常提醒」至门店群 + 区域运营
      │       │     2. 附带该店 vs 同加盟商其他店销量对比
      │       │     3. 建议上调该门店安全库存配置（单独配置）
      │       │     4. 记录异常根因为「单店销量异常」
      │       │
      │       └─ 否 → 【根因：正常消耗，建议按可用天数临界规则紧急订货】
      │             【系统动作】
      │             1. 自动推送「紧急订货提醒」至门店群
      │             2. 附带建议订货量 = 安全库存 × 1.5 − 期末库存
      │             3. 记录异常根因为「正常消耗致库存不足」
```

**关键检查清单**：

* [ ] 近 7 日销量是否突增？

* [ ] 近 3 日是否有到货未录入？

* [ ] 是否有在途调拨未签收？

* [ ] 同物料其他门店是否也预警？

* [ ] 安全库存天数是否需要季节性调整？

#### 规则 S2：可用天数临界

**判定逻辑**：可用天数 = 期末库存 / 日均消耗 ≤ 补货周期

**分级**：

- 🔴 可用天数 ≤ 补货周期：有断货风险

- 🟡 可用天数 ≤ 补货周期 × 1\.5：需关注

### 3\.2 周转效率类规则

#### 规则 T1：库存周转天数异常

**判定逻辑**：

- 周转天数 = 平均库存 / 日均消耗

- 🔴 周转天数 \> 品类建议天数上限 × 2（严重积压）

- 🟡 周转天数 \> 品类建议天数上限 × 1\.5（轻度积压）

**行业参考**：烘焙品牌实测，库存周转天数从 4\.8 天降至 3\.0 天，临期品损耗率同步下降 37%（来源：观远数据客户案例）。

#### 规则 T2：销入比失衡

**判定逻辑**：消耗量 / 入库量

|阈值|等级|含义|
|---|---|---|
|\> 2\.0|🔴|销远大于进，库存即将耗尽|
|1\.5\-2\.0|🟡|销大于进，需关注补货节奏|
|0\.3\-0\.5|🟡|进远大于销，有积压风险|
|\< 0\.3|🔴|严重滞销，需清货或停采|

**触发条件（MVP 已落地）**：消耗量 \> 入库量 × 2 → 标红，提示"销远大于进"

**排查决策树**：

```
步骤 1：判断销入比方向
  ├─ 销入比 > 2（销远大于进）→ 库存即将耗尽
  │   └─ 检查是否有到货未录入（参见 D2 步骤 1：收货未录排查）
  │   │   ├─ 是 → 【根因：收货未录】
  │   │   │     【系统动作】
  │   │   │     1. 自动推送「待收货提醒」至门店群，@店长
  │   │   │     2. 附带物流单号，要求确认签收并录入
  │   │   │     3. 24h 未确认自动升级推送总部运营群
  │   │   │     4. 记录异常根因为「收货未录导致销入比虚高」
  │   │   │
  │   │   └─ 否 → 检查近 7 日销量是否突增
  │   │       ├─ 是 → 【根因：销售上涨导致消耗加快】
  │   │       │     【系统动作】
  │   │       │     1. 自动推送「紧急补货提醒」至门店群 + 总部采购群
  │   │       │     2. 生成建议订货量，附带销量突增数据
  │   │       │     3. 触发「安全库存天数上调」建议（待总部确认）
  │   │       │     4. 记录异常根因为「销售突增」
  │   │       │
  │   │       └─ 否 → 检查安全库存天数是否设置过低
  │   │           ├─ 是 → 【根因：安全库存设置过低】
  │   │           │     【系统动作】
  │   │           │     1. 自动推送「配置调整建议」至总部运营群
  │   │           │     2. 附带当前 vs 建议安全库存天数对比
  │   │           │     3. 触发库存配置表更新审批流
  │   │           │     4. 记录异常根因为「安全库存配置偏低」
  │   │           │
  │   │           └─ 否 → 【根因：未知，需人工介入】
  │   │                 【系统动作】
  │   │                 1. 自动生成「异常调查工单」，分配给区域运营
  │   │                 2. 附带该物料近 30 天销入比趋势图
  │   │                 3. 标记为「待人工归因」
  │   │
  └─ 销入比 < 0.3（进远大于销）→ 严重滞销
      └─ 检查该 SKU 近 30 天销量趋势
      │   ├─ 持续下滑 → 【根因：销量持续下滑】
      │   │     【系统动作】
      │   │     1. 自动推送「滞销清货建议」至门店群 + 总部运营群
      │   │     2. 附带清货方案选项：促销 / 调拨 / 报损
      │   │     3. 生成「停采建议」，推送采购群，标记该 SKU
      │   │     4. 触发调拨推荐：匹配有需求的其他门店
      │   │     5. 记录异常根因为「销量持续下滑」
      │   │
      │   └─ 波动大 → 进入步骤 2
      └─ 检查是否为季节性物料
          ├─ 是 → 【根因：季节性积压】
          │     【系统动作】
          │     1. 自动推送「季节性调拨建议」至总部运营群
          │     2. 附带该物料在各门店的季节性销量分布
          │     3. 生成调拨建议：从低需求门店调至高需求门店
          │     4. 触发「淡季储备策略」提醒，建议下季度减少订货
          │     5. 记录异常根因为「季节性积压」
          │
          └─ 否 → 进入步骤 2

步骤 2：判断是否为周期性现象
  ├─ 每周固定某天销入比异常高 → 补货周期与消耗周期不匹配
  │   └─ 例如：周一集中到货，但周末消耗高峰 → 【根因：补货周期不匹配】
  │         【系统动作】
  │         1. 自动推送「补货周期调整建议」至门店群
  │         2. 附带当前周期 vs 建议周期对比（如周一到货 → 调整为周四到货）
  │         3. 触发订货日历调整建议
  │         4. 记录异常根因为「补货周期不匹配」
  │
  └─ 无规律 → 【根因：单品销售波动，需深入分析】
        【系统动作】
        1. 自动生成「单品分析工单」，分配给运营分析师
        2. 附带该 SKU 近 30 天销量、竞品活动、促销记录
        3. 触发「竞品监控」任务，抓取竞品同期动作
        4. 标记为「待人工分析」
```

**关键检查清单**：

* [ ] 销入比方向：销大于进 还是 进大于销？

* [ ] 近 7 日销量是否突增？

* [ ] 近 30 天销量趋势如何？

* [ ] 是否为季节性物料？

* [ ] 安全库存天数设置是否合理？

#### 规则 T3：呆滞库存预警

**判定逻辑**：

- 🔴 30 天无动销（零出库记录）

- 🟡 15 天无动销且库存量 \> 安全库存

**响应动作**：

- 触发清货预警，建议促销或调拨

- 纳入「滞销 SKU 处置建议」自动推送

### 3\.3 差异偏差类规则

#### 规则 D1：理论 vs 实际差异率

**判定逻辑**：差异率 = \|理论库存 − 实际盘点\| / 理论库存

|阈值|等级|含义|
|---|---|---|
|\> 50%|🔴|严重差异，必须复盘|
|10%\-50%|🟡|明显差异，建议核查|
|\< 10%|🟢|可接受范围|

**触发条件（MVP 已落地）**：\|理论 − 实际\| / 理论 \> 10% → 标黄

**排查决策树**：

```
步骤 1：判断差异方向
  ├─ 理论 > 实际（系统算多了）→ 可能漏盘、报损未录、物料损耗
  │   └─ 检查报损记录是否完整录入
  │   │   ├─ 否 → 【根因：报损未录】
  │   │   │     【系统动作】
  │   │   │     1. 自动推送「报损录入提醒」至门店群
  │   │   │     2. 附带近 7 天该物料的理论 vs 实际差异金额

  │   │   │     4. 记录异常根因为「报损未录」
  │   │   │

  │   │       ├─ 是 → 【根因：盘点误差】

  │   │       │     1. 自动推送「盘点复核提醒」至门店群

  │   │           │     1. 自动推送「损耗记录规范提醒」至门店群

  │   │           │     3. 建议门店建立「日常损耗登记」机制
  │   │           │     4. 记录异常根因为「日常损耗未记录」
  │   │           │
  │   │           └─ 否 → 【根因：未知，需人工介入】

  │   │                 1. 自动生成「差异调查工单」，分配给区域运营
  │   │                 2. 附带该物料近 3 次盘点记录对比
  │   │                 3. 标记为「待人工归因」
  │   │
  └─ 理论 < 实际（系统算少了）→ 可能多盘、收货未录、销售漏记

      │   │     3. 24h 未确认自动升级推送总部运营群

      │   │

      │       │     2. 附带 POS 销售总额 vs 系统销售明细差异
      │       │     3. 触发 IT 排查任务，检查接口同步状态
      │       │     4. 记录异常根因为「POS 数据同步异常」
      │       │

      │           │     3. 记录异常根因为「调拨入未录入」

步骤 2：判断差异是否持续
  ├─ 连续 3 个盘点周期同方向差异 → 【根因：系统性问题 概率高】

  │         3. 触发「配方核查任务」，分配给商品管理负责人
  │         4. 触发「系统日志排查任务」，分配给技术负责人
  │         5. 记录异常根因为「系统性问题（配方/漏录/换算/同步）」

        2. 附带盘点常见错误清单
```

#### 规则 D2：负库存告警

**判定逻辑**：理论库存 \< 0

**含义**：系统算出「欠货」，说明有货未录或消耗数据异常

**触发条件（MVP 已落地）**：理论库存 \< 0 → 标红，提示"库存为负，请核查"

**排查决策树**：

触发后按以下步骤排查，系统根据每一步结论自动执行对应动作：

```
步骤 1：检查近 3 日是否有该物料的入库记录
  ├─ 无入库记录，但有销售消耗 → 【根因：收货未录 / 未订货】
  │   └─ 询问门店：近期是否有到货未录入？或是否忘记向总部订货？
  │         【系统动作】
  │         1. 自动推送「待收货/待订货提醒」至门店群，@店长
  │         2. 附带近 7 天该物料消耗趋势 + 建议订货量
  │         3. 若门店确认「已到货未录」→ 下发「入库单补录」待办
  │         4. 若门店确认「未订货」→ 生成紧急订货单草稿，推送确认
  │         5. 24h 未响应自动升级推送总部运营群
  │         6. 记录异常根因为「收货未录或未订货」
  │
  ├─ 有入库记录，且销入比正常 → 【根因：消耗突增 / 销售上涨】
  │   └─ 检查近 7 日销量是否明显上升
  │       ├─ 是 → 【根因：销售上涨】
  │       │     【系统动作】
  │       │     1. 自动推送「紧急补货提醒」至门店群 + 总部采购群
  │       │     2. 生成建议订货量 = 安全库存 × 1.5 − 期末库存
  │       │     3. 触发「安全库存天数上调」建议
  │       │     4. 记录异常根因为「销售突增致负库存」
  │       │
  │       └─ 否 → 进入步骤 2
  │
  └─ 有入库记录，但入库量明显偏少 → 【根因：订货不足 / 供应商延迟】
      └─ 检查订货单 vs 入库单差异，确认供应商履约情况
      │   ├─ 订货量 = 入库量 → 【根因：订货不足】
      │   │     【系统动作】
      │   │     1. 自动推送「订货量不足提醒」至门店群
      │   │     2. 附带建议订货量（基于近 30 天日均消耗 × 补货周期）
      │   │     3. 记录异常根因为「订货量不足」
      │   │
      │   └─ 订货量 > 入库量 → 【根因：供应商延迟/少发】
      │         【系统动作】
      │         1. 自动推送「供应商履约异常」至采购群
      │         2. 附带订货单 vs 入库单对比
      │         3. 触发供应商投诉/催货流程
      │         4. 记录异常根因为「供应商延迟」

步骤 2：检查是否多门店同时出现该物料负库存
  ├─ 是（≥2 家门店同时负库存）→ 【根因：配方错误 概率高】
  │   └─ 核查商品档案中该物料的配方系数是否维护错误（如多写了一个 0）
  │         【系统动作】
  │         1. 自动推送「配方异常预警」至总部商品管理群
  │         2. 附带受影响的门店清单 + 该物料当前配方系数
  │         3. 触发「配方核查工单」，要求 4h 内确认
  │         4. 若确认配方错误 → 自动标记「需全量重算该物料历史消耗」
  │         5. 记录异常根因为「配方错误」
  │
  └─ 否（仅单店）→ 【根因：门店操作问题 概率高】
        【系统动作】
        1. 自动推送「门店操作核查提醒」至该门店群
        2. 附带步骤 1 的结论（收货未录/订货不足/销售突增）
        3. 要求门店店长确认并回复处理方案
        4. 24h 未回复自动升级推送区域运营
        5. 记录异常根因为「门店操作问题」
```

**关键检查清单**：

* [ ] 近 3 日入库流水是否有该物料？

* [ ] 近 7 日销量是否突增？

* [ ] 同 SKU 其他门店是否也负库存？

* [ ] 配方系数近期是否有变更？

#### 规则 D3：连续差异趋势

**判定逻辑**：同一物料连续 3 个盘点周期差异率 \> 10%

**含义**：不是偶发误差，而是系统性问题（如配方错误、持续漏录）

### 3\.4 损耗报废类规则

#### 规则 L1：损耗率超标

**判定逻辑**：损耗率 = \|理论 − 实际\| / 理论 × 100%

**行业基准**：

- 新茶饮行业原料损耗率平均 3%\-5%（来源：中国连锁经营协会 CCFA 行业调研）

- 其中约 60% 的损耗来自"备货过多导致过期"

**分级**：

|阈值|等级|
|---|---|
|\> 10%|🔴|
|5%\-10%|🟡|
|\< 5%|🟢|

#### 规则 L2：报损率异常

**判定逻辑**：报损率 = 报损量 / \(期初 \+ 入库\) × 100%

**分级**：

|阈值|等级|
|---|---|
|\> 5%|🔴|
|2%\-5%|🟡|
|\< 2%|🟢|

**响应动作**：

- 报损原因分布分析（破损/过期/变质/丢失/其他）

- 若"过期"占比高 → 触发安全库存天数下调建议

- 若"破损"占比高 → 触发供应商/物流核查

#### 规则 L3：临期预警

**判定逻辑**：

- 🔴 剩余保质期 \< 总保质期 × 20%（如 12 个月保质期剩余 \< 2\.4 个月）

- 🟡 剩余保质期 \< 总保质期 × 30%

**F\&B 特殊处理**：

- 鲜果/乳制品：按天数计算（剩余 \< 2 天标红）

- 茶叶/糖浆：按月份计算

---

### 3\.5 结构失衡类规则

#### 规则 B1：SKU 动销结构失衡

**判定逻辑**：按 ABC 分类法

|类别|定义|库存占比建议|异常判定|
|---|---|---|---|
|A 类|销售额占比前 20% 的 SKU|库存占比 70%\-80%|\< 70% → 🟡，\< 50% → 🔴|
|B 类|销售额占比 20%\-80% 的 SKU|库存占比 15%\-25%|偏离 ±10% → 🟡|
|C 类|销售额占比后 20% 的 SKU|库存占比 5%\-10%|\> 15% → 🟡，\> 25% → 🔴|

#### 规则 B2：热销品缺货 \+ 滞销品积压并存

**判定逻辑**：

- 存在 A 类 SKU 触发安全库存预警（🔴）

- 同时存在 C 类 SKU 触发呆滞预警（🔴）

**含义**：库存结构严重失衡，需立即调整订货策略

## 四、归因方法

### 4\.1 四档归因框架

与《门店间调拨 \& 总部库存研判》对齐，归因按置信度和复杂度分为四档：

|档位|方法|适用场景|成本/速度|
|---|---|---|---|
|**L1 规则匹配**|基于硬编码规则直接判定|信号极强、边界清晰的异常|极低 / 实时|
|**L2 基线偏离**|与历史同期/同门店基线对比|有充足历史数据的门店|低 / 实时|
|**L3 知识库推理**|结合 know\-how 知识库进行专家规则推理|需要领域知识的复杂场景|中 / 秒级|
|**L4 AI 推理**|大模型综合多源数据多步推理|前 3 档无法覆盖的模糊场景|高 / 秒级\~分钟级|

### 4\.2 六类根因与责任归属

所有异常最终可归为以下六类根因：

|根因|责任方|典型触发场景|L1 判定规则|
|---|---|---|---|
|**配方错误**|总部责任|理论消耗与实际偏差大，多门店同时出现|同 SKU 多门店差异率同时 \> 10%|
|**收货未录**|加盟商动作|理论库存为负、销入比异常高|理论库存 \< 0 且近期有入库单未录|
|**盘点误差**|加盟商动作|差异率波动大、无规律|差异率时正时负，无一致方向|
|**物料收错**|混合责任|入库数量与订货单不符|入库数量 ≠ 订货单数量|
|**销售异常**|混合责任|POS 漏单/退单未同步|销售明细与 POS 总额对不上|
|**系统/流程缺陷**|总部责任|自动化任务异常、单据重复|同单据号重复写入、单位换算错误|

### 4\.3 假阳性策略

为降低漏报风险，系统**先报全所有可能性**（列出所有可能根因及对应证据），由 UI 层提供筛选和排序能力。用户可在界面上快速排除明显不相关的归因方向，而非依赖系统预先剪掉。

### 4\.4 反馈闭环

每一次人工复核的结果（确认归因正确、纠正归因类别、标记"无法判断"）都会**回写异常记录**，形成带标签的训练样本，用于：

- 定期校准 L3 知识库规则

- 微调 L4 AI 推理模型的门店特异性表现

- 统计各类根因的真实分布，反哺阈值和预警策略优化

## 五、茶饮/F\&B 行业特有 Knowhow

### 5\.1 保质期驱动规则

F\&B 行业的库存管理与其他零售的最大区别：**保质期是硬约束，不是软建议**。

|策略|说明|
|---|---|
|**先进先出（FIFO）**|必须严格执行，系统应自动推荐「先使用临期批次」|
|**动态折扣**|临期品按剩余保质期比例自动建议折扣幅度|
|**保质期衰减系数**|剩余保质期 \< 20% 时，库存价值按 50% 计；\< 10% 时按 0 计|

### 5\.2 季节性波动规则

|场景|典型影响|规则调整|
|---|---|---|
|夏季旺季|冷饮原料消耗增加 30%\-50%|安全库存天数上调 20%|
|节假日|全品类销量突增|节前 3 天启动全品类备货|
|梅雨/台风|物流延迟概率增加|缓冲天数 \+1|
|新品上市|新 SKU 消耗预测不准|首周按保守估计 1\.2 倍备货|

### 5\.3 ABC 分类在茶饮中的应用

|类别|典型物料|管理策略|
|---|---|---|
|A 类|牛奶、核心茶叶、爆款糖浆|每日监控、自动补货、低安全库存天数|
|B 类|常规小料、次要茶叶|每周监控、定期补货|
|C 类|季节性物料、试销品|月度盘点、按需采购|

### 5\.4 加盟商 vs 直营店的差异

|维度|直营店|加盟店|
|---|---|---|
|安全库存|可按总部统一标准|需允许加盟商自主调整 ±20%|
|损耗容忍|总部承担|加盟商承担，需更严格阈值|
|补货触发|系统自动|系统建议 \+ 加盟商确认|
|异常归因|内部闭环|需明确责任方，避免扯皮|

### 5\.5 现做茶饮（Fresh\-Made）专项规则

> 本节针对「现做茶饮」——原料经配方\+操作即时转化为成品、小时级保质期、备料与销售强耦合——的库存异常判定做专项补充。与预包装商品（瓶罐饮料、零售包装零食）不同，现做茶饮的库存管理核心不在"有多少货"，而在"备了多少料、能在几小时内变成钱"。
> 
> 

---

#### 5\.5\.1 现做茶饮 vs 预包装商品：库存管理的核心差异

|维度|现做茶饮|预包装商品|
|---|---|---|
|**库存形态**|原料 \+ 半成品（茶汤、煮好的珍珠、切好的鲜果）|成品 SKU，直接上架销售|
|**保质期**|小时级（珍珠 4h、茶汤 2\-4h、鲜果切后 4h）|天\~月级|
|**损耗触发点**|备料环节（煮多了、泡多了、切多了）|滞销、过期|
|**BOM 复杂度**|高：杯型×糖量×冰量×加料组合|低：单一 SKU|
|**销售\-备料耦合**|极强：早高峰前必须备好料，晚高峰后剩余即损耗|弱：销售不直接影响库存形态|
|**盘点对象**|原料 \+ 半成品（需估重/估体积）|成品（点数即可）|

> **核心洞察**：现做茶饮的库存异常，70% 发生在"备料环节"而非"销售环节"。系统判定不能只盯着原料库存，必须把"半成品状态"纳入监控。
> 
>

#### 5\.5\.2 配方驱动的消耗与损耗

##### 配方精度是根基

现做茶饮的库存计算完全依赖 BOM（Bill of Materials）配方。配方误差会系统性放大到消耗计算、差异归因和损耗判定。

**MOMOYO 业务上下文示例**：

|成品|杯型|糖量|黑糖珍珠|黑糖冻|黑糖成品|果糖|冰块|半成品奶茶|
|---|---|---|---|---|---|---|---|---|
|黑糖珍珠奶茶|400ml|N|20g|20g|10g|10g|190g|150ml|
|黑糖珍珠奶茶|400ml|LS|20g|20g|10g|20g|190g|150ml|
|黑糖珍珠奶茶|500ml|N|70g|30g|10g|10g|120g|240ml|
|黑糖珍珠奶茶|500ml|LS|70g|30g|10g|25g|120g|240ml|
|黑糖珍珠奶茶|700B|N|90g|30g|10g|15g|230g|270ml|
|黑糖珍珠奶茶|700B|LS|90g|30g|10g|20g|230g|270ml|

> 同一成品 1 个，因杯型和糖量变体产生 6 个 SKU，配方差异最大达 4\.5 倍（黑糖珍珠 20g→90g）。系统必须按 SKU 级配方精确计算消耗，不能按"平均配方"估算。
> 
> 

##### 配方变更的连锁反应

**判定规则 F1：配方变更触发全量重算**

|场景|判定逻辑|响应动作|
|---|---|---|
|总部调整 BOM|商品档案配方字段变更|自动标记"配方变更日"，该日及之后消耗按新配方计算|
|新品上市|新 SKU 首次有销售记录|首周按保守估计 1\.2 倍备货，系统记录"新品观察期"|
|配方被门店擅自修改|实际消耗与标准配方差异率 \> 15%|触发"配方执行异常"告警，核查 SOP 执行|

> **来源**：KwickOS 平台数据，Tiger Sugar 2 家门店因配方执行不一致，每年产生 $5,000-$8,000 的成本差异（KwickOS, 2026）。
> 
> 

##### 杯型/糖量/冰量变体的库存影响

**判定规则 F2：变体销量结构偏移预警**

```
逻辑：某日某物料实际消耗 vs 按标准销量结构推算的理论消耗
偏移率 = |实际消耗 − 理论消耗| / 理论消耗
```

|阈值|等级|含义|
|---|---|---|
|\> 20%|🔴|变体销量结构发生显著偏移（如大杯突然爆卖）|
|10%\-20%|🟡|变体结构轻微偏移，需关注|
|\< 10%|🟢|正常波动|

**典型场景**：夏季大杯销量占比从 30% 升至 55%，黑糖珍珠消耗量激增 80%。若不按 SKU 级配方计算，安全库存会系统性不足。

#### 5\.5\.3 备料\-销售耦合管理

##### 备料环节是损耗重灾区

现做茶饮的备料（Prep）指在营业前或低峰期预制的半成品：煮珍珠、泡茶汤、切鲜果、预制奶盖等。备料量 ≠ 库存量，而是"已投入、待销售、有时限"的中间态。

**行业数据**：

- 煮好的珍珠保质期约 4 小时，过期后硬化不可售。多数门店因"怕断货"过量备料，浪费率 20%\-35%（KwickOS, 2026）。

- 预制茶汤（绿茶/红茶/乌龙）常温放置 2\-4 小时后风味显著下降，建议冷藏并在 4 小时内使用（天津隆顺兴食品, 2026）。

- 鲜果切后 4 小时内用完，榨汁后需密封冷藏且 4 小时内使用（天津隆顺兴食品, 2026）。

**判定规则 P1：备料损耗率监控**

```
备料损耗率 = 备料总量中未在保质期内转化为销售的量 / 备料总量 × 100%
```

|品类|建议备料损耗率上限|超出阈值含义|
|---|---|---|
|煮好的珍珠|15%|批量过大或时段预测不准|
|预制茶汤|10%|泡茶量与销售节奏不匹配|
|切好的鲜果|20%|预估销量偏高或切配过早|
|预制奶盖|10%|制作批次不合理|

**响应动作**：

- 🔴 备料损耗率连续 3 天超标 → 触发"备料策略优化建议"，推送"按时段销量分批次备料"方案

- 🟡 单日超标 → 记录备料日志，次日推送"昨日备料复盘"

##### 按时段备料（Time\-Based Prep）

**判定规则 P2：时段销量预测与备料建议**

|时段|典型特征|备料策略|
|---|---|---|
|早高峰前（开店前 1h）|需备全天 30%\-40% 基础料|按昨日同期销量 × 1\.1 备料|
|午高峰前（11:00）|需补足上午消耗|按 10:00\-11:00 实时销量动态调整|
|下午茶高峰前（14:00）|水果茶需求上升|按天气\+历史数据调整鲜果备料|
|晚高峰前（17:00）|最后一波高峰|保守备料，避免打烊前大量剩余|

> **来源**：有赞新零售茶饮行业 AI 库存管理方案，"按时段销量分批次备料"可使珍珠浪费率降低 40%（有赞新零售, 2026）。
> 
> 

##### 半成品库存的"时间价值衰减"

**判定规则 P3：半成品临期价值衰减**

现做茶饮的半成品不同于普通原料，其价值随时间指数衰减：

|剩余保质期占比|价值系数|库存计价|
|---|---|---|
|\> 50%|100%|按全额成本计|
|25%\-50%|70%|按 70% 成本计，建议优先使用|
|10%\-25%|30%|按 30% 成本计，建议促销或内部消化|
|\< 10%|0%|视为已损耗，不计入可用库存|

> 与 5\.1 节"保质期衰减系数"的区别：5\.1 针对原料保质期（天/月级），本节针对半成品保质期（小时级），衰减更陡峭。
> 
>

#### 5\.5\.4 现做茶饮特有的损耗类型与根因

##### 六大现做损耗类型

|损耗类型|发生环节|典型根因|系统判定线索|
|---|---|---|---|
|**煮制过量**|珍珠/小料煮制|怕断货心理、批量煮制习惯|珍珠消耗量 vs 销量理论值差异 \> 20%|
|**茶汤过期**|泡茶/储茶|泡茶过早、储茶容器未密封|茶汤类物料无销售但消耗记录存在|
|**操作差异**|出品环节|店员凭手感加料、未用量杯|同 SKU 不同班次消耗差异 \> 15%|
|**鲜果氧化**|切配/储放|切后暴露过久、未密封冷藏|鲜果损耗率显著高于同类门店均值|
|**试饮/损耗**|日常运营|试饮、打翻、给员工|报损单中"破损/试饮"占比高|
|**杯袋错配**|出杯打包|杯型与包装袋不匹配|包材消耗与杯数不成比例|

> **来源**：用友畅捷通好生意奶茶损耗管理系统行业案例，某新式茶饮连锁企业引入损耗管理系统后，每月损耗成本下降超 20%（畅捷通, 2026）。
> 
> 

##### 操作差异（Overportioning）专项

**判定规则 O1：操作差异率**

```
操作差异率 = (实际消耗 − 理论消耗) / 理论消耗 × 100%
```

|阈值|等级|含义|
|---|---|---|
|\> 15%|🔴|严重超量操作，需立即培训|
|8%\-15%|🟡|轻微超量，需提醒|
|\< 8%|🟢|正常范围（含合理损耗）|

**根因细分**：

- 若**同门店不同班次**差异大 → 培训问题（早班 vs 晚班操作不一致）

- 若**多门店同 SKU** 差异大 → 配方问题（总部配方不统一或执行不到位）

- 若**特定店员** consistently 偏高 → 个人操作习惯问题

> **来源**：KwickOS 平台数据，15g 的珍珠加料差异在 200 杯/天的门店中，年损失 $1,752（KwickOS, 2026）。
> 
>

#### 5\.5\.5 现做茶饮的异常判定增强规则

在母手册第 3 章通用规则基础上，现做茶饮需增加以下专项规则：

##### 规则 FM1：半成品安全库存

**判定逻辑**：半成品库存（煮好的珍珠、预制茶汤等）\< 时段预计销量 × 1\.5 倍 BOM 用量

|等级|条件|响应|
|---|---|---|
|🔴|半成品库存 \< 高峰 2h 预计销量|立即触发紧急备料提醒|
|🟡|半成品库存 \< 高峰 4h 预计销量|建议关注，准备备料|

##### 规则 FM2：备料\-销售时差异常

**判定逻辑**：备料完成时间 − 销售高峰开始时间 \> 2 小时

**含义**：备料过早，半成品在高峰来临前已衰减
**响应**：推送"备料时间优化建议"，建议按时段分批备料

##### 规则 FM3：时段消耗波动

**判定逻辑**：同一 SKU 相邻时段（如 10:00\-11:00 vs 11:00\-12:00）消耗量波动 \> 50%

**含义**：可能存在备料节奏与销售节奏不匹配
**响应**：标记"时段波动异常"，建议分析原因（天气/活动/周边事件）

##### 规则 FM4：成品\-原料消耗比异常

**判定逻辑**：某时段成品销量 × BOM 理论用量 vs 实际原料消耗

```
消耗比 = 实际原料消耗 / (成品销量 × BOM 用量)
```

|阈值|等级|含义|
|---|---|---|
|\> 1\.3|🔴|严重超耗（操作差异\+备料浪费）|
|1\.1\-1\.3|🟡|轻度超耗|
|0\.9\-1\.1|🟢|正常|
|\< 0\.9|🔴|消耗低于理论（可能漏记销售或配方错误）|

##### 规则 FM5：跨杯型物料消耗结构偏移

**判定逻辑**：某日各杯型销量占比 vs 历史同期，导致某物料消耗量异常

**示例**：

```
历史：400ml 占 50% / 500ml 占 30% / 700B 占 20%
今日：400ml 占 20% / 500ml 占 30% / 700B 占 50%
→ 黑糖珍珠消耗量理论值应上升 55%
若实际未上升 → 可能配方执行异常或销量统计错误
```

### 8\.1 术语表

|术语|定义|
|---|---|
|安全库存|为应对不确定性而保留的最低库存量|
|补货周期|从下单到货物到店的时间|
|缓冲天数|应对突发情况的额外天数|
|销入比|消耗量 / 入库量，衡量进货与销售匹配度|
|差异率|\|理论库存 − 实际盘点\| / 理论库存|
|损耗率|不可解释的差异占比|
|报损率|报损量占可用库存的比例|
|可用天数|期末库存 / 日均消耗|
|周转天数|平均库存 / 日均消耗|
|呆滞库存|超过设定天数无动销的库存|

> **现做茶饮补充术语**
> 
> 

|术语|定义|
|---|---|
|**备料（Prep）**|营业前预制的半成品：煮珍珠、泡茶汤、切鲜果等|
|**操作差异率**|\(实际消耗 − 理论消耗\) / 理论消耗 × 100%，衡量配方执行精度|
|**备料损耗率**|未在保质期内转化为销售的备料量 / 备料总量 × 100%|
|**半成品安全库存**|时段预计销量 × 1\.5 倍 BOM 用量的备料缓冲量|
|**变体销量结构**|同一成品不同杯型/糖量/冰量的销量占比分布|
|**消耗比**|实际原料消耗 / \(成品销量 × BOM 理论用量\)|
|**时间价值衰减**|半成品随保质期减少而价值指数下降（小时级）|
